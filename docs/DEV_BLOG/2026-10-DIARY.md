## 2026-10-16: profile key patch-2.22v5.5.4 stays

The profile key in `docs/bfme1-manifest.json` stays `patch-2.22v5.5.4`. It is
historical. The data version is Patch 2.22v7.0.5 (`displayVersion`, from
`lotr.str` key `Version:Format2` in `_patch222.big`). Android selects the

bump. `GameDataManifest` reads only known keys. The engine does not parse
this file. `tools/datacheck` reads its own archive `manifest.json`, not this
one. The profile now has `profileKeyNote`. `schemaVersion` stays 1. No engine
or Android code change.

## 2026-10-16: E1-38 BFME ControlBar.wnd command buttons

Pixel run 3 died with SIGSEGV at 0x14 in `ControlBar::init`:
`ControlBar.wnd:ControlBarParent` was null. BFME still ships the Zero Hour
`ControlBar.wnd` with every window name the code asks for, but its fifteen
command buttons say `WINDOWTYPE = COMMANDBUTTON`. Zero Hour has no gadget of
that type, so `createGadget` returned nullptr, `parseChildWindows` failed and
the whole tree was destroyed up to the parent. In lenient mode that type is
now read as `PUSHBUTTON` (the buttons already have `STYLE = PUSHBUTTON`).
`ControlBar::init` logs and stops if the parent is still missing. A headless
linux64 run then stopped on `Data\INI\ChallengeMode`, which BFME does not
have; lenient mode now skips an INI directory with no files. Headless
`GameEngine::init` now finishes and pushes `Menus/MainMenu.wnd`, which BFME
does not have either (`Shell::doPush` already returns on a null layout).

## 2026-10-16: E1-51 render targets stay color attachments

Review of `e0645b839`. `CreateTexture` no longer rejects every
`D3DUSAGE_RENDERTARGET`. The GLES backend already binds those textures to an
FBO (`setRenderTarget`) and reads them back (`readbackRenderTarget`). Pillarbox
creates an A8R8G8B8 offscreen target that way (`dx8wrapper.cpp`), and the same
flag is used for shader render targets. `D3DERR_NOTAVAILABLE` is now only for
a format that cannot be a color attachment: L8, A8, A8L8, and DXT. RGBA8,
RGB565, RGBA4 and RGB5_A1 still succeed.

## 2026-10-16: GlobalLighting v7 (K5, PR #46)

`ParseLightingDataChunk` reads BFME v7 as nine lights per time of day
(terrain, object, infantry × sun and two accents), stores the 44-byte tail
raw, and rejects every version except 1, 2, 3 and 7 before it writes anything.
A v7 body whose tail is not `4*9*36+4+44` bytes after the time-of-day int is
rejected the same way, so a short chunk is not read past its end. v1–v3 stay
in the Zero Hour order. Infantry diffuse and direction go to the existing
`m_infantryLight` path; slot-0 infantry ambient becomes `m_infantryAmbient`
only when the v7 flag is set. `doTheLight` still bakes the three terrain
lights. `REAL_TO_INT` is unchanged. On d3d8gles the light map is the existing
`TerrainShader2Stage` NOISE12 pass, not a new shader.

## 2026-10-16: ADR-0005 cliff class carries its page

Third lead review. A cliff vertex needs the class `page` as well as `origin`
and `size`: the same rectangle on another page is a different class. Eastfold
on four full 2048 pages peaks at 172.4 MiB in the memory table, by the same
upload accounting as Trilogy. `dx8wrapper.cpp:3898–3902` is
`Create_Render_Target`, not the atlas path.

## 2026-10-08: ADR-0005 cliff UVs wrap inside the class

Second lead review of the terrain ADR. BFME cliff UVs do not sit inside the
atlas class rectangle; Zero Hour adds them to the class corner with no wrap.
M1 samples a cliff cell as `origin + fract(local) * size` and uses
`textureGrad` from the unwrapped derivatives, so the mip does not jump on the
seam. The 4 px gutter already repeats the opposite edge of the class. A
texture array is no longer rejected because of cliff UVs. The real cons are
equal layer size, the 256-layer minimum, and `sampler2D` only. Maps with more
than 1568 cells use 2048 pages even when 4096 is available. M1 acceptance LOD
is High.

## 2026-10-08: ADR-0005 terrain on GLES 3.0 (draft, review)

Rewrote `docs/adr/ADR-0005-terrain-gles3.md` after the engine-lead review.
BFME terrain on d3d8gles is three fixed-function passes (cloud and light map
are on in the game data; night drops the cloud). M1 is one 4096×2048 atlas
when `GL_MAX_TEXTURE_SIZE` is at least 4096. Patch 2.22 needs 2048 pages
(Trilogy is five). A texture array stays out. The 42 MiB figure was not an
upper bound: the GPU mip chain, the CPU shadow copy, and per-tile `TileData`
all sit in memory together.

## 2026-10-08: kernel thread id on Linux and Android

`ThreadClass::_Get_Current_Thread_ID()` returned 0 under `_UNIX`, so the DX8
main-thread checks compared 0 with 0. On Linux and Android it now returns the
kernel TID (`gettid()`, `_GNU_SOURCE` before the first libc header). `pthread_self()`
does not fit in the `unsigned` return on LP64 and is not the id in logcat.
Windows still calls `GetCurrentThreadId()`. The logic-thread bind in ADR-0003
stays on `std::thread::id`; this function is not that check.

Headless never calls `WW3D::Init` (`W3DDisplay.cpp:1163`), so
`_MainThreadID` stays 0. After this function returns a real tid, a raw
compare is false for the whole run: loads go to the queue, and
`ThreadClass::Execute` does not start the loader on `_UNIX`.
`TextureLoader::Is_DX8_Thread()` now returns true while the stored id is
still 0, and compares tids after `DX8Wrapper::Init` (`dx8wrapper.cpp:718`).
The three `Unlock_Surfaces` asserts use that function too.

Unit test: `tests/thread` (two threads, stable main id). Before Init the
DX8-thread check is true; after Init a different thread is false. NDK is
not in this environment, so there is no Android link of the engine here.

## 2026-10-08: E1-51 terrain atlas 4096×2048, pages of 2048

The ZH packer fits 784 tiles on one 2048² page and drops the rest at the first
free cell of a row. Fords of Isen (984 tiles) loses 17 classes that way.
Trilogy is 3396 tiles, which does not fit in 4096² either (3136 slots).

When `GL_MAX_TEXTURE_SIZE` is at least 4096 and the map fits, the atlas is one
4096×2048 texture. Otherwise it is square 2048 pages. A class stays on one
page, so a side of 15 or more takes a whole 2048 page (Eastfold 4, Trilogy 5).
Tile indices are checked before the table is touched. Overflow is logged like
the blend anomalies: 16 detail lines, then a summary. Cliff u/v stay local
class units (1 is one class edge, no wrap). `getCliffClassInfo` returns the
page plus origin and size in that page's UV; the shader samples
`origin + fract(local) * size`. `getUVForNdx` and `getUVForBlend` also return
the page. Atlas mipmaps stop at 3 levels so trilinear filtering does not blend
across the 4px border. The path follows the queried max texture size, which
`FillCaps` reports. `CreateTexture` returns `D3DERR_INVALIDCALL`,
`D3DERR_NOTAVAILABLE` or `D3DERR_OUTOFVIDEOMEMORY` instead of always succeeding.

Synthetic tests cover Fords, Eastfold and Trilogy. The 115 real maps are still
for the team machine.

## 2026-10-08: GameMath on musl, flag still off

E1-49. GameMath is musl 1.2.5 libm under `Core/Libraries/Source/GameMath`,
with the MIT text in `LICENSES/`. Public names are renamed (`sin` becomes
`gm_musl_sin`) so libc stays libc, and `__FP_FAST_FMA` is undefined so
x86_64 and arm64 take the same non-fma path. `SAGE_USE_DETERMINISTIC_MATH`
stays OFF. The bit-exact test builds here and prints
`SKIP: qemu-aarch64 is not available`. A skip is not a pass.

`REAL_TO_INT_FLOOR` / `REAL_TO_INT_CEIL` are the same ZH macros. The note
next to them follows ADR-0003 §2.7 from bfme `9bd874f3e`: floor of −n is
−n−1, ceil of +n is n+1, a known quirk, and new code uses
`GameMath::floorToInt32` / `ceilToInt32`.

The CI scripts catch `crc()` calling `xfer(` (the one exception is
`AIUpdateInterface`), ban `long` / `lroundf` / `lrintf` / `long double` in
logic, and fail if someone "fixes" those two macros. FPCR R1 in the ADR is
the runtime `fp::` hooks, not a grep, and `fp.h` is a separate change, so
this does not invent a static FPCR check.

`wwmath.h` calls GameMath only inside `USE_DETERMINISTIC_MATH`. `Trig.cpp`
and `PhysicsUpdate.cpp:793` are still on the platform libm, because the
flag is off.

The musl library is `gamemath_lib.cmake`, included from `cmake/gamemath.cmake`
only when the flag is on, and from `tests/gamemath`. This branch does not add
`CMakeLists.txt` in that directory: that file is the fp gate's. The
`GameMath.h` include sits in front of `class WWMath`. An include inside the
class does not compile. `-I GameMath/include` is added only when the flag is
on. `floorToInt32` is `Lib/GameMathInt.h`. The host check compares against
`tests/gamemath/host_hashes_x86_64.txt` (x86_64, `-ffp-contract=off`). arm64
is not in that file.

## 2026-10-08: logic-thread FP gate (ADR-0003 §2.3)

`fp::bindLogicThread()` is the first call in `GameMain()`, before the engine
init. `GameLogic::init` and `setFPMode()` compare `std::thread::id`. Debug and
CI abort on a mismatch or on a check that happened before the bind. Release
logs once; if nothing was bound yet, that log is followed by binding the
caller. A second bind from another thread aborts only in debug. The Android
debug thread-name check warns when the name is not `SDLThread` and does not
abort. `gettid()` is only in the log line.

`setFPMode()` is a wrapper over `fp::reset()`. The stub's `reset()` is the
previous non-VC6 body (`fesetenv`, `feclearexcept`, `fesetround(FE_TONEAREST)`,
and on x86 the x87 control word and MXCSR nearest). `read()` and
`isExpected()` stay trivial until Platform replaces the file. VC6 still
compiles the old `setFPMode()` in place. `g_mode` is `std::atomic` and is
read and written with relaxed ordering.

## 2026-10-08: E1-17b GLES backend is not an Android ifdef

`d3d8gles` was compiled only when CMake saw `ANDROID`, and the engine's
GLES fixes were `#if defined(__ANDROID__)`. A desktop Linux build could
not select the same backend. `SAGE_USE_D3D8GLES` is ON for the Android
preset and OFF for `linux64-deploy`. GLES fixes (UV origin, half-pixel
bias, smudge readback, the D3D8 entry point, draw-category counters)
follow that macro. Where the fix would be wrong under DXVK, the existing
`d3d8gles_ShouldUseVulkanBackend()` check still decides. Window, touch,
font paths, FFmpeg and the Android storage path stay on `__ANDROID__`.

Desktop with the option ON keeps DXVK unless the env token selects GLES
(the review note above is the token table).
Mesa then loads `libGLESv2.so.2` through an EGL window.
`SAGE_D3D8GLES_FORCE_DXT_CPU` or `GENERALSX_D3D8GLES_FORCE_DXT_CPU=1`
forces the CPU DXT decode, because llvmpipe advertises S3TC and Mali does
not. Both default off, so an Android run still trusts the extension string.

## 2026-10-02: `-gxCrcLog` for QA replay tests

QA needs the logic CRC of every frame in its own file, without turning on the
network trace. `-gxCrcLog <path>` writes `bfme-crclog/1` (frame CRC plus the
running CRC after Objects, Partition, PlayerList, and AI). It is off unless
the option is passed. The checksum is the existing `getCRC(CRC_RECALC)` path,
Xfer in CRC mode, and the logic seed is only read.

The exit footer remembers the last frame written. `atexit` runs after
`GameLogic` is gone, so it must not call `getFrame()`. With `-jobs N` the
parent only spawns workers; those workers now receive the option and each
opens `<stem>.<replay>.<pid><ext>`. `-jobs 1` is what QA should use. The
header records `# logic_hz=` because the replay file does not store the tick
rate (30 unless the 60 Hz build is on).

Not run here: a headless replay. The first one should show the same final CRC
and gamestats with and without the flag, and should check the suspected +1
offset (CRCs in the replay sit on frames 1, 101, 201, …).
