# Доступ к файлам BFME1 на телефоне: дизайн

- Автор: «Android-платформа», 02.10.2026. Статус: черновик к ADR-0002 (п. 5b), на согласовании с Лидом движка.
- Жёсткое правило (TEAM.md): файлы игры EA никогда не попадают в APK, git или на сервер. Пользователь берёт их из своей копии.
- Ссылки на форк: `B = https://github.com/MYSOREZ/GeneralsZH-Android-Port/blob/8ef2349`.

## 1. Рекомендация (коротко)

Движок работает **только из каталога приложения `getExternalFilesDir(null)/GameData/`**: обычные пути и `fopen`/`chdir`, без разрешений, как в форке. При первом запуске пользователь выбирает папку со своей BFME1 (1.03 + Patch 2.22) через **SAF `ACTION_OPEN_DOCUMENT_TREE`**. Мы **потоково копируем** её к себе, по ходу считаем SHA-256 и сверяем с манифестом, показываем прогресс и итог проверки, после чего пользователь может удалить исходник. Читать `.big` прямо из SAF не стоит: каждое открытие идёт через binder и FUSE, случайное чтение не кэшируется, а движок открывает по путям сотни файлов. Запасные пути — копирование через USB (MTP) или `adb push` в `Android/data/<pkg>/files/GameData`. `MANAGE_EXTERNAL_STORAGE` (путь форка) держим только как опцию сборки «для своих».

## 2. Варианты

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. SAF + копирование в `getExternalFilesDir`** (рекомендуется) | `ACTION_OPEN_DOCUMENT_TREE`, `takePersistableUriPermission(READ)`, обход через `DocumentsContract` (не `DocumentFile`), копирование через `openFileDescriptor` → наш каталог | нет особых разрешений; движок работает с обычными путями; одна проверка целостности при импорте; файлы на быстром пути (каталог приложения) | во время импорта нужно вдвое больше места (если исходник на телефоне); после удаления приложения каталог стирается, нужен повторный импорт; импорт занимает минуты |
| B. SAF + копирование во внутреннее хранилище (`filesDir`) | то же, в `/data/data/<pkg>/files` | не виден никому, не проходит через FUSE | файлы нельзя ни положить, ни проверить извне; тоже стирается при удалении; для 2.22 и патчей неудобно |
| C. Прямое чтение через SAF (fd без копирования) | для каждого `.big` `openFileDescriptor(uri,"r")`, нативный `pread` по fd | нет копии, экономия места | VFS движка придётся переписать с путей на fd; все отдельные файлы (INI-переопределения, карты, Options/сохранения) через SAF; разрешение на дерево может пропасть (перемещение папки, очистка); FUSE и binder на каждое открытие |
| D. Пользователь сам копирует в `Android/data/<pkg>/files` | файловый менеджер, MTP или adb | ноль кода импорта | с Android 11 SAF не даёт выбрать `Android/data`, и встроенный «Файлы» на многих прошивках туда не пускает, так что реально только через ПК (MTP/adb) **[MTP на Pixel не проверено]**; нет проверки целостности; форк от этого пути ушёл |
| E. `MANAGE_EXTERNAL_STORAGE` + любая папка (как в форке) | «All files access», `java.io.File`, движок читает папку пользователя | нет копии, любой файловый менеджер | широкое разрешение, в Google Play ограничено политикой; на `/sdcard` FUSE медленнее каталога приложения; проверку целостности всё равно писать самим |

Факты, на которых это стоит:
- Android 11+: `ACTION_OPEN_DOCUMENT_TREE` не даёт выбрать корень внутреннего хранилища, `Download/` и `Android/data/`, `Android/obb/` (https://developer.android.com/about/versions/11/privacy/storage, https://developer.android.com/training/data-storage/shared/documents-files). Обход через `EXTRA_INITIAL_URI` на `Android/data` закрывают обновлениями приложения «Файлы», работает не везде (https://www.lonelycatgames.com/docs/xplore/known-problems/no-android-data). Опираться на него нельзя.
- Форк MYSOREZ сознательно не стал использовать SAF: «hands back a content:// tree the engine's plain fopen()/chdir() can't use without copying the whole 2-3 GB game data first». Выбрал `MANAGE_EXTERNAL_STORAGE` + `requestLegacyExternalStorage` (B/android/app/src/main/AndroidManifest.xml#L38, #L87; B/docs/port/ANDROID_PORT.md §4, §6). Пользовательские данные (Options.ini, сохранения) у него лежат во внутреннем хранилище через `HOME`.
- FUSE: с Android 11 внешнее хранилище эмулируется через FUSE. Даже с passthrough (Android 12+) «random read operations, where no caching or read-ahead can help» медленнее, а доступ по `/sdcard/` даёт «noticeable performance drops» (https://source.android.com/docs/core/storage/fuse-passthrough).
- Замер fadi-labib на Galaxy S22 Ultra: 3496 отдельных DDS с `/sdcard` читались 16,6 с, один `TexturesZH.big` 0,6 с (~30×). Загрузка с отдельными файлами ~5 мин, с одним архивом 7 с (https://github.com/fadi-labib/Generals-Android/issues/9). Вывод: держать данные в `.big`, а не распаковывать.
- `DocumentFile.listFiles()` медленный (отдельный запрос на каждый файл). Обходить через `DocumentsContract.buildChildDocumentsUriUsingTree` + один `query` с проекцией `DOCUMENT_ID, DISPLAY_NAME, MIME_TYPE, SIZE, LAST_MODIFIED` (https://commonsware.com/blog/2019/11/23/scoped-storage-stories-documentscontract.html).

## 3. Объём данных

- **По источникам:** PC-версия требует 3,5 ГБ (CNCNZ, https://cncnz.com/games/battle-for-middle-earth/system-requirements/; MobyGames, https://www.mobygames.com/game/15857/the-lord-of-the-rings-the-battle-for-middle-earth/specs/) или 4 ГБ свободного места (GameReplays FAQ, https://www.gamereplays.org/community/index.php?showtopic=449714). Подтверждения «~6 ГБ» не нашёл. Для сравнения: ресурсы ZH занимают 2,7 ГБ (форк).
- **Замер на боксе, 02.10.2026 17:22 МСК, `/workspace/bfme-mobile/gamedata/`:** `du -sh` = **103 МБ** (107 779 656 байт). Лежат **только 2 архива**, полной копии нет:

| Файл | Байт | Записей | Сигнатура | SHA-256 |
|---|---|---|---|---|
| `ini.big` | 13 513 985 | 242 (`data\ini\*.ini`) | `BIG4` | `f5220a9357c467d5ed8499dc9140d2d995e487abd8ba08216dba7496782e8156` |
| `maps.big` | 94 265 671 | 372 (`maps\…`) | `BIG4` | `499d60ebd3c37d556dfbba4b0f0cb92bc893c94f8ca3d720b4a7125a91a368d4` |

  Заметка для «Форматов и данных»: сигнатура BFME1 **`BIG4`**, а не `BIGF`, как в Generals. VFS должна принимать обе.
- **Что делать:** полный размер установки (1.03 + 2.22 v5.5.4 + HD-текстуры 2.22) замерить, когда появится полная копия. Бюджет места на телефоне: размер копии плюс ~10% запаса, а при импорте с того же телефона ×2, пока исходник не удалён. При перекодировке текстур (см. `gpu-driver-issues.md` №1) к этому добавляется размер перекодированного архива текстур, RGBA8 примерно в 4–8 раз больше DXT.

## 4. Проверка целостности

- **Манифест** `bfme1-manifest.json` встроен в APK. Содержит **только метаданные** (имена, размеры, SHA-256), без контента EA. Собирает «Форматы и данные» по копии Андрея на боксе, в одном профиле `patch-2.22v5.5.4`.
- **Проверки при импорте:**
  1. Обязательные файлы есть, например `ini.big`, `maps.big`, текстуры, W3D, звук, английский или русский `lang` (точный список дадут «Форматы и данные»).
  2. Размеры совпадают.
  3. SHA-256 считаем потоково во время копирования, без второго чтения.
  4. Определяем версию: 1.03 / 2.22 по совпадению хешей ключевых архивов. При неизвестном хеше выдаём предупреждение «модифицированная копия», а не ошибку, пусть решает пользователь.
- **При запуске:** быстрая проверка размера и mtime по сохранённому `import-state.json`. Полный пересчёт хешей по кнопке «Проверить файлы».
- **Наш мобильный слой INI** (переопределения поверх 2.22) лежит отдельно, в `files/MobileLayer/`, и в манифест оригинала не входит.

## 5. Раскладка каталогов на телефоне

```
/storage/emulated/0/Android/data/<pkg>/files/
  GameData/            ← копия BFME1 (только чтение для движка), cwd движка
  MobileLayer/         ← наши INI-переопределения (идёт в APK как assets, распаковывается)
  import-state.json    ← источник, профиль, хеши, дата
/data/data/<pkg>/files/ ← HOME: Options.ini, сохранения, реплеи, логи и crash.log (как в форке)
/data/data/<pkg>/cache/ ← кэш шейдеров (glProgramBinary / DXVK)
```

## 6. UX первого запуска

1. **Экран «Нужны файлы BFME1».** Коротко: что нужно (своя копия 1.03 + Patch 2.22), сколько места (по манифесту) и сколько свободно (`StatFs`). Кнопки: **«Выбрать папку с игрой»**, «Как скопировать с ПК» (инструкция для MTP/adb), «Логи».
2. **Выбор папки** через SAF. Подсказка: «скопируйте папку игры с ПК в Download/BFME1 или в Documents/BFME1, затем выберите её». Сам `Download/` целиком выбрать нельзя, только подпапку. После выбора папки вызываем `takePersistableUriPermission`.
3. **Предпроверка** (быстро, без чтения содержимого): список файлов и размеры против манифеста, определение профиля 1.03 / 2.22, проверка места. Итог: зелёный, жёлтый («модифицировано» или «нет 2.22») или красный («не хватает файлов: …»).
4. **Импорт** в `WorkManager`/foreground-сервисе с уведомлением: копирование с прогрессом (МБ, скорость, оставшееся время) и потоковый SHA-256. Возобновляется после прерывания по файлам (уже проверенные пропускаем). Экран не обязан быть включён.
5. **Итог:** «Готово, версия 2.22v5.5.4, N файлов проверено». Кнопка «Удалить исходную папку» (через SAF, только с подтверждения пользователя), затем «Играть».
6. **Следующие запуски:** быстрая проверка и сразу игра. Если файлов нет (пользователь очистил данные), возвращаемся к шагу 1.
7. **Обновление патча** (новая 2.22): «Обновить файлы» → тот же импорт, копируются только изменённые по хешу.

## Решение Лида 02.10.2026

Закреплено в `docs/adr/ADR-0002-target-devices.md` §9 и `docs/E1-BACKLOG.md`:
- Принят вариант **A**: движок читает только `getExternalFilesDir(null)/GameData/`, SAF-импорт с потоковым копированием и SHA-256 делаем **в Э1** (E1-12a). Запасной путь D (MTP/adb).
- `MANAGE_EXTERNAL_STORAGE` и `requestLegacyExternalStorage` убираем, когда заработает импорт (E1-12b). Отладочная сборка с ними остаётся открытым вопросом (ADR-0002 §12 п. 6).
- Манифест `bfme1-manifest.json` (только метаданные) и список обязательных файлов делают «Форматы и данные» (E1-24) по полной копии Андрея. Полная копия на боксе есть, 351/351.
- VFS принимает обе сигнатуры, `BIG4` (BFME1) и `BIGF` (Generals), порядок BFME1 → 2.22 → `MobileLayer/` (E1-21, E1-22).
- Перекодированные текстуры кладём в кэш внутри `getExternalFilesDir` (как производные данных EA, они не попадают в git, APK и на сервер). Место под них учитываем в бюджете §3 (вопрос §7 п. 2 решён: на телефоне при импорте, по триггеру).

## Политика полей манифеста

К `docs/bfme1-manifest.json` (schemaVersion 1):

- Пути записаны в нижнем регистре. Сравнение при импорте — без учёта регистра.
- `required` значит: без этого файла движок не дойдёт до карты M1.
- `displayVersion` — строка для экрана импорта, не id профиля.

`displayVersion` взят из `_patch222.big` → `data/lotr.str`, ключ `Version:Format2`. С надписью в меню ПК пока не сверен (§2.1 чек-листа); до сверки QA не считает его доказанной строкой экрана.

- `kind` есть у каждого файла. Без `kind` Android считает файл импортируемым. `big` — сигнатура `BIGF` или `BIG4`; `win-binary` — PE, в телефон не копируется; `loose` — остальное.
- Новые поля добавляются без смены `schemaVersion`. Удаление или переименование поля — это `schemaVersion` 2.
