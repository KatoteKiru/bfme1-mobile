## 0. Как пользоваться чек-листом

1. Шаги идут по порядку. У каждого шага три строки: **Что сделать**, **Ожидаемо**, **Если не так**.
2. **Общее правило «если не так»:**
   - сделайте скриншот (кнопка питания + громкость вниз) или запись экрана (шторка → «Запись экрана»);
   - запишите номер шага и что увидели, в шаблон из раздела 3;
   - если приложение живо, переходите к следующему шагу; если оно закрылось само («Приложение остановлено», чёрный экран, вылет на рабочий стол), повторите шаг ещё 2 раза, затем сделайте шаг 1.14 «Отправить отчёт» и пришлите всё Оркестратору.
3. **Ничего специального не нужно:** ни режима разработчика, ни разблокировки загрузчика, ни root, ни adb. adb — только как необязательная альтернатива, если он у вас уже есть (не утверждённое требование, `TEST-PLAN.md` §1 п. 2).
4. **Файлы игры EA** берутся только из вашей собственной установки BFME1 2.22. Никуда их не отправляйте и не выкладывайте: ни в облако, ни в мессенджер, ни в GitHub. Скриншоты из игры отправляйте только Оркестратору (в них графика EA, `TEST-PLAN.md` §6.6).
5. **Время:** Часть 1 — около 40 минут (включая crash-selftest и native smoke). Часть 2 — около 90 минут: тестовый набор Форматов (~665 МБ) загружается три раза (импорт 2.3, повторный импорт 2.10, необязательный adb/MTP 2.11), каждый раз 3–10 мин на Pixel 8 Pro; полный набор — TBD.

### 0.1 Что сейчас в промежуточном APK (E1-04 + E1-15 + вырезание обновлений/GO)
- **Пакет:** `io.github.katotekiru.me1mobile` (свой ключ подписи). Со старым приложением форка **«GeneralsZH»** (`com.generalsx.zerohour`) **не конфликтует**. Если «GeneralsZH» ещё стоит с тестовых установок — **удалите его заранее** (иначе путаница со значками и логами).
- **Имя на рабочем столе (черновик):** «**ME1 Mobile**». **versionName:** `0.1.0-<sha7>` (семь символов коммита — те же, что в имени файла APK).
- **Лаунчер Setup** открывается без краша. Карточек «Обновления», GeneralsOnline и DataPack **нет** (вырезаны как блокер; без этого APK #1 Андрею не отдаётся).
- **«Запустить игру» без данных** показывает диалог «**Нужны файлы игры**» (или неактивную кнопку + текст) и **не** загружает native-код — краша быть не должно. Полный экран «Нужны файлы BFME1» — с E1-12a (Часть 2).
- **Логи (E1-15):** кнопка «**Отправить отчёт**» (`bfme-report_*.zip` через FileProvider, список с галочками, «Сохранить в файл», автопредложение после краша). «Поделиться» форка остаётся запасным путём для сырых логов. Кнопка «**Проверить краш-отчёт**» (crash-selftest) и native smoke (libmain/EGL без GameData) — без файлов EA.
- **Не входит в промежуточный APK:** E1-13 (масштаб), E1-14 (pacing/Swappy), E1-35 (темп логики) — **ожиданий по плавности в Части 1 нет**.
- **`allowBackup="false"`** в тестовых сборках: после переустановки настройки и путь к данным **не** восстанавливаются.

## Часть 1. Запуск и логи (без данных игры)

### 1.1 Что вы получите

**Что сделать:** взять у Оркестратора два файла (ручная сборка на боксе `tools/build-apk.sh`; sha256 сообщает Оркестратор):
- `bfme-zh-<7 символов коммита>.apk` — само приложение, около **40–45 МБ**;
- `bfme-zh-<коммит>.apk.sha256` — текстовый файл из одной строки: 64 символа контрольной суммы, два пробела, имя APK. Например: `5ef54c11…f293457  bfme-zh-d1079b0.apk`.

**Ожидаемо:** имена обоих файлов содержат один и тот же код коммита. Его же запишите в отчёт — он должен совпасть с хвостом `versionName` (`0.1.0-<sha7>`, шаг 1.10).

**Если не так:** нет файла `.sha256` или коды в именах разные — не устанавливайте, напишите Оркестратору.

### 1.2 Проверка sha256
Сумма доказывает, что вы ставите ровно тот файл, который собрали на боксе.

**Что сделать (основной путь — ПК с Windows):**
1. Положите оба файла в одну папку, например «Загрузки».
2. Откройте PowerShell (Пуск → набрать «PowerShell») и выполните, подставив своё имя файла:
   ```
   Get-FileHash "$env:USERPROFILE\Downloads\bfme-zh-XXXXXXX.apk" -Algorithm SHA256
   ```
   Вариант без PowerShell (командная строка `cmd`): `certutil -hashfile "%USERPROFILE%\Downloads\bfme-zh-XXXXXXX.apk" SHA256`.
3. Откройте `.sha256` в Блокноте и сравните **все 64 символа**. Регистр не важен: PowerShell печатает заглавными, файл — строчными.
   - На macOS: `shasum -a 256 bfme-zh-XXXXXXX.apk`; на Linux: `sha256sum -c bfme-zh-XXXXXXX.apk.sha256` (должно быть `OK`).

**На телефоне (необязательно):** встроенной проверки суммы на Pixel нет. Если APK скачан прямо на телефон, можно проверить его любым приложением подсчёта хешей, которому вы доверяете; если такого нет, перешлите тот же файл на ПК и проверьте там.

**Ожидаемо:** суммы совпадают полностью.

**Если не так:** **не устанавливайте.** Скачайте файл заново; если сумма снова другая, сообщите Оркестратору оба значения.

### 1.3 Перенос APK на телефон

**Что сделать (один из вариантов):**
- **Кабель USB-C:** подключите телефон к ПК → на телефоне в уведомлении «Зарядка через USB» нажмите → выберите «Передача файлов». На ПК в Проводнике откройте «Pixel 8 Pro» → «Внутренний общий накопитель» → `Download` и скопируйте туда APK.
- **Прямо на телефоне:** скачайте APK из того же чата, где его прислали. Chrome может предупредить «Файл может быть опасен» — выберите «Всё равно скачать».

**Ожидаемо:** в приложении «Файлы» → «Загрузки» виден `bfme-zh-….apk` того же размера.

**Если не так:** размер другой или файл не открывается — скачайте ещё раз и повторите 1.2.

### 1.4 Установка

**Перед установкой:** если на телефоне ещё стоит старое тестовое **«GeneralsZH»** (`com.generalsx.zerohour`) — удалите его (долгое нажатие → «Удалить»). Наш пакет другой (`io.github.katotekiru.me1mobile`), конфликта подписи с форком больше нет, но два значка и путаница с логами не нужны.

**Что сделать:**
1. «Файлы» → «Загрузки» → нажмите на `bfme-zh-….apk`.
2. Android скажет, что установка неизвестных приложений из этого источника запрещена → «Настройки» → включите «Разрешить установку из этого источника» → «Назад». (Если ставите из Chrome или Telegram, разрешение спросят для этого приложения.)
3. «Установить».
4. **Play Protect** может показать «Приложение заблокировано» / «Play Protect не знает этого разработчика» (APK подписан **нашим** ключом, не из Google Play). Нажмите «Подробнее» → «Всё равно установить». Если предложит «Отправить приложение на проверку» — «Не отправлять» (репозиторий приватный).
5. «Готово» (не «Открыть»: перед первым запуском нужен шаг 1.6).

**Ожидаемо:** установка завершается за 10–30 секунд; на рабочем столе и в списке приложений появляется **один** значок **«ME1 Mobile»** (черновик имени).

**Если не так:**
- «Приложение не установлено» / «пакет конфликтует с существующим»: уже стоит сборка с тем же `applicationId`, но с другой подписью. Пришлите скриншот; дальше по 1.16 (удалить старое, предварительно отправив отчёт).
- «Пакет повреждён» / «Ошибка синтаксического анализа»: файл испорчен, вернитесь к 1.2.
- Play Protect не даёт кнопки «Всё равно установить» (только «ОК»): остановитесь, скриншот Оркестратору.

> **Альтернатива для тех, у кого уже есть adb (необязательно):** на телефоне включена «Отладка по USB», на ПК: `adb install -r bfme-zh-XXXXXXX.apk` → ответ `Success`. Логи через `adb logcat` можно приложить, но приёмка на них не опирается.

### 1.5 Данные устройства (записать один раз перед стартом)
Перенесите в раздел «Устройство» отчёта (шаблон в разделе 3).

### 1.6 Первый запуск без данных игры (режим полёта — страховка)

**Что сделать:**
1. Включите **режим полёта** (шторка → «Режим полёта»). Зачем: страховка на случай, если в сборке остался сетевой код; штатно UpdateManager / GeneralsOnline / GXRemoteConfig уже вырезаны (блокер E1-04).
2. Нажмите значок «ME1 Mobile».

**Ожидаемо:**
- через 1–3 секунды открывается экран лаунчера (Setup) **без краша**, в портретной ориентации;
- на «Главной»: кнопка «Запустить игру», карточка «Папка с игрой» (или эквивалент), **нет** карточек «Обновления», GeneralsOnline и DataPack (подробнее — 1.7);
- **ни одного системного запроса разрешений** при первом запуске (до выбора папки / импорта);
- не закрывается, не зависает; язык лаунчера — язык телефона.

⚠ Полный экран «Нужны файлы BFME1» с объёмом «нужно / свободно» и кнопками «Выбрать папку с игрой», «Как скопировать с ПК», «Логи» — **ещё не реализовано — уточнить при APK с E1-12a.** В промежуточном APK достаточно лаунчера без краша.

**Если не так:**
- «Приложение остановлено» или вылет на рабочий стол — **падение лаунчера**: повторите 2 раза, скриншоты, сразу к 1.14.
- Запасной / упрощённый экран настроек — скриншот (текст в скобках важен), дальше можно продолжать.

### 1.7 Нет обновлений / GeneralsOnline; сеть не качает

**Что сделать:**
1. На «Главной» прокрутите весь экран вниз. Сделайте скриншот(ы) всей «Главной».
2. Убедитесь, что **нет** карточки «**Обновления**», **нет** карточек GeneralsOnline и DataPack.
3. Выключите режим полёта, включите **Wi‑Fi**.
4. Закройте приложение (смахнуть из недавних), снова откройте «ME1 Mobile», подождите ~30 секунд на «Главной».
5. Настройки → Приложения → ME1 Mobile → «Мобильный трафик и Wi‑Fi» (или «Использование данных»): посмотрите трафик **фоновый** и **на переднем плане** после этого открытия.

**Ожидаемо:** карточек «Обновления» / GeneralsOnline / DataPack нет; после открытия с Wi‑Fi трафик приложения остаётся **~0** (единицы килобайт допустимы на DNS/системный шум; мегабайтных скачиваний быть не должно). Никаких тостов про «новый движок» / «сетевые данные».

**Если не так:** есть карточка «Обновления» или GeneralsOnline/DataPack, или трафик явно растёт (сотни КБ / МБ) — **блокер**, скриншоты + цифры трафика Оркестратору. Дальше Часть 1 можно продолжать только по указанию Оркестратора.

### 1.8 «Запустить игру» без данных

**Что сделать:** «Главная» → «Запустить игру». Повторите 3 раза.

**Ожидаемо:** появляется диалог «**Нужны файлы игры**» **или** кнопка неактивна и рядом поясняющий текст. Приложение **остаётся в лаунчере**, **не** загружает native-код (`libmain.so`) и **не** падает. Нет чёрного экрана дольше 5 секунд, нет «Приложение остановлено».

⚠ Полный экран «Нужны файлы BFME1» (E1-12a) — **ещё не реализовано — уточнить при APK с E1-12a.**

**Если не так:** чёрный экран > 5 с, зависание, вылет, краш native без данных — скриншот или запись экрана, затем 1.14 (**блокер**).

### 1.9 Диалоги разрешений (до E1-12b)

**Что сделать:**
1. «Главная» → «Выбрать папку с игрой» (если кнопки ещё нет — ⏭ и запишите в отчёт).
2. Если появится подсказка про «Доступ ко всем файлам» / системный экран «Доступ ко всем файлам» — **не включайте** переключатель. Нажмите «Назад».
3. Настройки телефона → Приложения → ME1 Mobile → «Разрешения»: сделайте скриншот списка. Если «Доступ ко всем файлам» / «Файлы и медиа» **уже был выдан** ранее — **напишите это в отчёте** (и по возможности отзовите).

**Ожидаемо:** после «Назад» вы снова в лаунчере, без вылета. В «Разрешениях» «Доступ ко всем файлам» **не** выдан.

**Почему не включать:** старый путь форка (`MANAGE_EXTERNAL_STORAGE` / `requestLegacyExternalStorage`) уходит **после E1-12a** (задача E1-12b). До этого Андрею сказано не выдавать «Доступ ко всем файлам».

⚠ В APK с E1-12b запроса «Доступ ко всем файлам» быть **не должно**. Если кнопка сразу открывает системный выбор папки (SAF) — это уже Часть 2: нажмите «Назад» (отмена) и проверьте, что лаунчер не упал.

**Если не так:** вылет после «Назад» — скриншот, 1.14.

### 1.10 Видеокарта и версия (скриншоты)

**Что сделать:**
1. Вкладка «Графика» (если есть): скриншот карточки «Графический бэкенд» (строки «Ваш GPU: …» и «Сейчас: …»). **Бэкенд не меняйте.**
2. Вкладка «Справка» (или аналог): скриншот с **versionName**.
3. Сверьте хвост версии с семью символами коммита в **имени файла APK** из 1.1.

**Ожидаемо:** «Ваш GPU: Mali-G715…» (если карточка есть), «Сейчас: OpenGL ES (по умолчанию)» (`ADR-0002` §3). **versionName** вида **`0.1.0-<sha7>`**, где `<sha7>` **совпадает** с кодом в имени `bfme-zh-<sha7>.apk`.

**Если не так:** другой GPU / бэкенд по умолчанию, или sha в versionName ≠ имени APK — скриншот, продолжайте (несовпадение sha — дефект сборки, отметить в отчёте).

### 1.11 Поворот экрана

**Что сделать:** включите автоповорот (шторка → «Автоповорот»). На вкладках «Главная» и «Инструменты» (или доступных) поверните телефон: портрет → альбом → портрет, по 2 раза.

**Ожидаемо:** экран перестраивается за долю секунды, остаётся та же вкладка, текст не обрезан, нет пустого экрана, нет вылета.

**Если не так:** скриншот в той ориентации, где плохо.

### 1.12 Свернуть и вернуться

**Что сделать:**
1. На «Главной» сделайте жест «Домой», подождите 30 секунд, верните приложение через список недавних (свайп снизу и задержка).
2. То же с другой вкладки, если есть.
3. Заблокируйте экран кнопкой питания на 10 секунд, разблокируйте.

**Ожидаемо:** лаунчер возвращается на ту же вкладку без перезапуска и без вылета.

**Если не так:** вернулся не на ту вкладку — запишите (minor); вылет или пустой экран — скриншот, 1.14 (сбой после возврата — major по `TEST-PLAN.md` §3.1).

### 1.13 Холодный перезапуск

**Что сделать:**
1. Настройки → Приложения → ME1 Mobile → «Остановить» → «ОК». Запустите значок снова.
2. Перезагрузите телефон, после загрузки запустите приложение (это «холодный старт» по `TEST-PLAN.md` §5.2).

**Ожидаемо:** оба раза лаунчер открывается за 1–3 секунды на «Главной»; карточек «Обновления»/GO по-прежнему нет; «Папка с игрой» не задана (если такой индикатор есть).

**Если не так:** вылет — скриншот, 1.14.

### 1.14 «Отправить отчёт» и запасной «Поделиться»

**Что сделать:**
1. Найдите в лаунчере кнопку «**Отправить отчёт**» (E1-15; рядом может быть просмотр логов форка).
2. Откройте её: должен быть **список файлов с галочками**, варианты отправить и «**Сохранить в файл**».
3. Отправьте отчёт в чат с Оркестратором **или** сохраните zip и перешлите файл. Имя вида `bfme-report_<версия>_<причина>_<дата-время>_<сессия>.zip` (через FileProvider).
4. Запасной путь: вкладка «Инструменты» → «Просмотреть логи» → «**Поделиться**» (сырые логи форка, `generalszh-logs.zip` или аналог) — если «Отправить отчёт» недоступна. Кнопку «Очистить логи» **не нажимайте**.

**Ожидаемо:** zip уходит / сохраняется; в Части 1 без native-запуска часть разделов может быть пустой — это нормально до шагов 1.15–1.16. Автопредложение после краша проверяется в 1.15.

**Куда отправлять:** только Оркестратору, в тот же чат, откуда пришёл APK. Не в GitHub и не в открытые чаты.

**Если не так:** нет кнопки «Отправить отчёт», ошибка подготовки zip — скриншот; попробуйте «Поделиться» как запасной путь и отметьте в отчёте.

### 1.15 Crash-selftest («Проверить краш-отчёт»)

**Что сделать:**
1. В лаунчере нажмите «**Проверить краш-отчёт**» (crash-selftest; может быть в «Инструменты» / «Тесты QA»).
2. Дождитесь аварийного завершения / возврата.
3. Снова откройте приложение: должно появиться **автопредложение** «Прошлый запуск завершился с ошибкой. Отправить отчёт?» (или близкий текст) с кнопками «Отправить» / «Сохранить в файл» / «Не сейчас».
4. Нажмите «Отправить» (или «Сохранить в файл» и перешлите zip Оркестратору).

**Ожидаемо:** автопредложение появляется; уходит / сохраняется `bfme-report_*.zip` с причиной краша. Файлы EA **не нужны**.

**Если не так:** нет кнопки, нет автопредложения, zip не создаётся — скриншоты, запасной «Поделиться» (1.14), Оркестратору (**для QA это важный регресс E1-15**).

### 1.16 Native smoke (libmain / EGL без GameData)

**Что сделать:**
1. В лаунчере запустите **native smoke-тест** (кнопка / пункт вроде «Native smoke» / сценарий без GameData — как подпишет Платформа в сборке).
2. Дождитесь завершения: тест грузит `libmain`/EGL, пишет в лог устройство / GPU / драйвер / surface и **штатно выходит** (без краша).
3. «Отправить отчёт» (1.14) — приложите отчёт к сообщению Оркестратору.

**Ожидаемо:** выход без «Приложение остановлено»; в отчёте есть строки про устройство, GPU, драйвер, surface (см. §4.2). Файлы EA **не нужны**.

**Если не так:** краш при загрузке `.so` / EGL — скриншот, 1.14 (**блокер** на эталоне).

### 1.17 Удаление и переустановка

**Что нужно знать:**
- **Сначала отчёт, потом удаление.** Удаление стирает приложение: логи, настройки и (после E1-12a) импортированную копию в `Android/data/io.github.katotekiru.me1mobile/files/GameData`.
- **Новая сборка поверх старой** ставится как обычно (1.4), данные сохраняются, если `applicationId` и подпись те же. Сборку отличайте по `versionName` / имени APK.
- «Приложение не установлено» при установке поверх — другая подпись: отправьте отчёт (1.14), удалите, поставьте заново.
- В тестовых сборках **`allowBackup="false"`**: после переустановки настройки и путь к данным **не** должны вернуться из резервной копии Google.

**Проверка (в конце Части 1, ≈ 3 мин):** 1.14 → удалить (долгое нажатие на значок → «Удалить», или Настройки → Приложения → ME1 Mobile → «Удалить») → поставить тот же APK (1.4) → запустить.

**Ожидаемо:** **чистое** состояние: папка с игрой / путь к данным **не** восстановлены, настройки лаунчера сброшены (не «как было до удаления»).

**Если не так:** настройки или путь к данным вернулись после переустановки — **дефект** (`allowBackup` или иной бэкап), скриншот, 1.14; вылет после переустановки — скриншот, 1.14.

## Часть 2. SAF-импорт данных игры

> ⚠ **Вся Часть 2 — ещё не реализовано — уточнить при APK с E1-12a** (E1-12a SAF-импорт, E1-24 манифест, E1-12b, E1-21/E1-21b чтение архивов BFME1). Ниже — **черновик UX** по ответам Платформы и `game-files-access.md` §6. Названия кнопок ниже — целевые; начинайте Часть 2, только когда Оркестратор скажет, что APK это умеет. Фотографируйте каждый новый экран.

### 2.1 Какие файлы взять с ПК

**Что сделать:**
1. На своём ПК откройте папку установки BFME1 с Patch 2.22 (у вас это `C:\BFME1`; в главном меню игры в углу строка «Patch 2.22v7.0.5»).
2. Проверьте, что в ней прямо в корне лежат архивы `.big`: `ini.big`, `maps.big`, `w3d.big`, `textures.big`, `terrain.big`, `audio.big`, `music.big`, `ambientstreams.big`, `shaders.big` и пять файлов патча `_patch222.big`, `_patch222bases.big`, `_patch222libraries.big`, `_patch222maps.big`, `_patch222textures.big`; рядом папки `lang` (там `englishaudio.big` и другие языковые архивы), `apt`, `data`.
3. **Копируйте папку целиком** (или тестовый набор Форматов — см. ниже). По замеру вашей полной копии это **351 файл, ≈ 3,6 ГиБ** (`DATA-VERSION.md`). Программы (`lotrbfme.exe`, `worldbuilder.exe`, `*.dll`) **на телефоне не нужны** (мешать не будут). Точный обязательный список — зона Форматов (E1-24). **Тестовый манифест E1-12a:** `ini.big` + `maps.big` + 5×`_patch222*` (Formats test set ≈ **665 МБ**, 7 файлов).

**Важно:** только ваша собственная легальная копия. Не скачивайте игру или патч из интернета, не берите чужую папку, не загружайте файлы в облако, мессенджер или на GitHub — только кабелем на свой телефон. Версия данных — **2.22 v7.0.5**. При совпадении хешей с манифестом предупреждения «модифицированная копия» быть **не должно**; если появляется — это **дефект**.

**Если не так:** нет `_patch222*.big` — патч 2.22 не установлен; остановитесь и напишите Оркестратору.

### 2.2 Перенос папки на телефон

**Что сделать:**
1. Проверьте свободное место (Настройки → Хранилище): для полного набора нужно **не меньше 8 ГБ** — копия в «Загрузках» плюс копия внутри приложения плюс ~10 % запаса (`game-files-access.md` §3). Для Formats test set (~665 МБ) достаточно ~1,5–2 ГБ свободно.
2. Подключите кабель, выберите «Передача файлов» (как в 1.3).
3. В Проводнике: «Pixel 8 Pro» → «Внутренний общий накопитель» → `Download` → создайте папку **`BFME1`** → скопируйте в неё **содержимое** `C:\BFME1` (чтобы `ini.big` лежал прямо в `Download\BFME1`). Подойдёт и `Documents\BFME1`.
4. Не кладите файлы прямо в `Download` без подпапки и не пытайтесь положить в `Android/data`: системный выбор папки не даёт выбрать корень `Download` и `Android/data` (ограничение Android 11+).

**Ожидаемо:** Formats test set (~665 МБ) — порядка минут; полный набор 3,6 ГиБ — **3–15 минут [оценка, полный размер/время E1-24 — TBD]**; в «Файлах» в `Download/BFME1` видны те же файлы.

**Если не так:** Windows пишет об ошибке копирования или размер другой — скопируйте папку заново; сфотографируйте ошибку.

### 2.3 Импорт через системный выбор папки (SAF)

**Что сделать:**
1. Запустите приложение. Ожидается экран «Нужны файлы BFME1» с объёмом «нужно / свободно» и кнопками «**Выбрать папку с игрой**», «**Как скопировать с ПК**», «**Логи**».
2. «Выбрать папку с игрой» → системный экран выбора папки → ☰ → «Pixel 8 Pro» → `Download` → `BFME1` → «**Использовать эту папку**».
3. Android спросит доступ к файлам в папке BFME1 → «**Разрешить**».
4. Перед копированием Android 13+ спросит «Разрешить приложению ME1 Mobile отправлять уведомления?» (**`POST_NOTIFICATIONS`**). **Оба ответа допустимы:** разрешение нужно только для уведомления с прогрессом в шторке, сам импорт от него не зависит. В этом первом импорте лучше нажать «**Разрешить**»; противоположный ответ проверяется во втором импорте (2.10). Запишите ответ в отчёт — по нему выбирается ветка проверки 2.4а.

**Ожидаемо (черновик UX E1-12a):**
- никакого «Доступ ко всем файлам» (после E1-12b его нет совсем; до E1-12b — не выдавать, см. 1.9);
- **предпроверка** за несколько секунд: список/размеры с манифестом, место через StatFs. Итог: **зелёный** («версия 2.22 v7.0.5»), **жёлтый** («модифицированная копия» / «нет 2.22» — при **совпадающих** хешах v7.0.5 жёлтого «модифицированная копия» быть не должно = дефект), **красный** («не хватает файлов» / мало места — импорт не начнётся);
- кнопка начала импорта.

**Если не так:** красный итог с полной/тестовой папкой, жёлтый «модифицированная копия» при чистой v7.0.5, вылет после «Разрешить» — скриншоты, 1.14.

### 2.4 Прогресс, время, размер

**Ожидаемо:**
- экран прогресса: МБ из скольких, скорость, оставшееся время; уведомление в шторке (если `POST_NOTIFICATIONS` разрешены);
- **экран можно выключить, приложение можно свернуть или смахнуть из недавних** — импорт продолжится при любом ответе на запрос уведомлений (foreground-сервис, проверка 2.4а);
- **Formats test set (~665 МБ, 7 файлов) на Pixel 8 Pro: около 3–10 мин**; полный набор — **TBD** (E1-24);
- итог: «**Готово, версия 2.22v7.0.5, N файлов проверено**» и кнопки «Играть» и «Удалить исходную папку»;
- `import-state.json` и лог импорта лежат в `getExternalFilesDir(null)/` рядом с `GameData/`; лог импорта входит в «Отправить отчёт».
- **Не удаляйте исходную папку**, пока не пройдёте 2.7–2.11 и QA не подтвердит отчёт.

**Если не так:** прогресс стоит > 30 с, время сильно больше оценки, итог без «проверено» — запись экрана, 1.14. Запишите фактическое время.

### 2.4а Импорт в фоне: уведомления разрешены / запрещены

Импорт всегда идёт в **foreground-сервисе** Android. Разрешение на уведомления для него **не обязательно**: если уведомления запрещены, уведомления в шторке не будет, но сервис работает и виден в списке «**Активные приложения**» (Android 13+). Проверяем обе ветки: одну — в первом импорте (2.3–2.4), другую — во втором импорте (2.10).

**Где список «Активные приложения»:** проведите от верхнего края экрана вниз **два раза** (полностью раскрытые быстрые настройки) → внизу кнопка «**N активных приложений**» (или «Активные приложения») → нажмите, откроется список. Кнопку «Остановить» напротив ME1 Mobile **не нажимайте**.

**Что сделать** (сразу, как только пошёл прогресс; тестовый набор копируется 3–10 минут, поэтому без пауз):
1. Сфотографируйте экран прогресса: сколько МБ уже скопировано.
2. Опустите шторку: есть ли уведомление «Импорт BFME1» с прогрессом. Откройте «Активные приложения»: есть ли там ME1 Mobile. Скриншот.
3. Сверните приложение жестом «Домой». Подождите 1 минуту. Снова откройте «Активные приложения» — скриншот.
4. Откройте список недавних (свайп снизу с задержкой) и **смахните ME1 Mobile вверх**. Подождите 1 минуту. Снова «Активные приложения» — скриншот.
5. Откройте ME1 Mobile значком на рабочем столе.

**Ожидаемо:**

| | Ветка А: уведомления **разрешены** | Ветка Б: уведомления **запрещены** |
|---|---|---|
| Уведомление в шторке (шаги 2–4) | есть, с прогрессом; остаётся после сворачивания и смахивания | **нет** — это нормально |
| ME1 Mobile в «Активных приложениях» (шаги 2–4) | есть | **есть** — и после сворачивания, и после смахивания |
| Просьба «не сворачивать» / «оставить экран открытым» | нет | **нет** |
| После повторного открытия (шаг 5) | прогресс больше, чем на шаге 1, копирование не началось с нуля; или уже итог «Готово … N файлов проверено» | то же |

В обеих ветках итог тот же, что в 2.4: «Готово, версия 2.22v7.0.5, N файлов проверено», без повторного копирования уже проверенных файлов. Когда импорт закончился, ME1 Mobile из «Активных приложений» пропадает.

**Если не так:** импорт остановился после сворачивания или смахивания, начался с нуля, ME1 Mobile нет в «Активных приложениях» во время копирования, приложение просит не уходить с экрана — скриншоты шагов 1–5 или запись экрана, затем 1.14; в отчёте укажите ветку (А/Б). Это **major**. Если после продолжения данные испорчены (итог без «проверено», ошибки хешей) — **блокер**, ничего не удаляйте.

### 2.5 Отмена и прерывание

**Что сделать (по одному разу, в любом порядке):**
1. Во время импорта нажмите «**Отмена**» → снова запустите импорт.
2. Во время импорта смахните приложение из списка недавних → откройте снова.
3. Во время импорта выключите экран на 1 минуту → включите.

**Ожидаемо:** «Отмена» **сохраняет частично скопированные файлы** и при повторе **продолжает с того же места** (не с нуля). После 2 импорт **не прерывается** (как в 2.4а, шаг 4): при открытии виден текущий прогресс; если 2.4а уже пройден в этом импорте, пункт 2 можно отметить по нему. После 3 импорт не прерывался. В итоге то же «N файлов проверено». Никаких вылетов.

**Если не так:** импорт с нуля после «Отмена» — запишите (major); после продолжения порча данных — **блокер** (`TEST-PLAN.md` §3.3): не удаляйте ничего, 1.14.

### 2.6 Мало места
Специально забивать память **не нужно**. Проверяйте, только если места и правда мало.

**Ожидаемо:**
- **до копирования:** предпроверка (манифест + StatFs) показывает **красный** экран «нужно X / свободно Y» и **не начинает** копирование;
- **во время копирования:** остановка с понятной ошибкой; после освобождения места — **возобновление** с места остановки.

**Если не так:** вылет, «зависший» прогресс без сообщения, «успех» при нехватке места — скриншоты, 1.14.

### 2.7 Второй запуск — до главного меню

**Что сделать:** закройте приложение (смахнуть из недавних), запустите снова → «Запустить игру».

**Ожидаемо:** быстрая проверка без повторного копирования; игра в альбомной ориентации; загрузка без чёрного экрана > 30 с без движения; главное меню BFME1 со строкой «Patch 2.22v7.0.5» в углу.

⚠ Главное меню BFME1 требует чтения архивов BFME1 и INI 2.22 (E1-21/E1-21b, E1-56, E1-36) — **ещё не реализовано — уточнить при APK с E1-12a**, что в этой сборке считается «дошли».

**Если не так:** вылет на загрузке, бесконечная загрузка, магента / чёрные текстуры — скриншот, 1.14. На Pixel 8 Pro это **блокеры** (`TEST-PLAN.md` §3.3).

### 2.7а Текст и шрифты в игре

**Что сделать:** в главном меню BFME1 (2.7) рассмотрите все надписи: пункты меню, кнопки, строку «Patch 2.22v7.0.5». Сделайте **скриншот главного меню** — он обязателен для отчёта.

**Ожидаемо:** все надписи читаются; нет кнопок без текста, нет пустых прямоугольников или квадратиков (□) вместо букв, нет «каши» из символов. Язык меню — язык вашей копии игры (обычно английский).

⚠ Если в этой сборке до главного меню ещё не доходим (см. 2.7), проверьте любой экран игры с текстом (загрузка, подсказки) и отметьте ⚠ в отчёте.

**Если не так:** скриншот места, где нет текста или квадратики вместо букв; 1.14. Пустые надписи в меню на Pixel 8 Pro — **major** (меню не пройти).

### 2.8 Короткий smoke-тест (2–3 минуты игры)

**Что сделать:**
1. Главное меню → «Схватка» (Skirmish) → карта **Fords of Isen** (запасная — Westfold) → любая фракция → «Начать».
2. 2–3 минуты: камера одним пальцем, щипок, поворот двумя пальцами, выделение здания/отряда.
3. Выход через меню игры → главное меню → выход из игры.
4. Если есть счётчик FPS (E1-39) — сфотографируйте в середине.

**Ожидаемо:** карта загружается (цель Э1 — ≤ 30 с), нет вылетов, нет магенты и чёрных пятен, касания попадают куда надо; выход в меню, потом в лаунчер.

**Известное, не отдельная ошибка:** пока нет E1-13 / E1-14 / E1-35 — **ожиданий по плавности нет** (в промежуточном APK их нет; в APK с данными до этих задач темп/кадры могут быть «как получится»). AI и скрипты карты в Э1 отключены (E1-37).

⚠ Схватка BFME1 на телефоне — цель вех M2–M3 — **ещё не реализовано — уточнить при APK с E1-12a.**

**Если не так:** запись экрана места проблемы, 1.14.

### 2.9 Повторный импорт, разрешения, MTP (необязательно)

**Ожидаемо:**
- **«Проверить файлы»** — полный пересчёт SHA-256; итог «N файлов проверено» без ошибок.
- **«Обновить файлы»** — при новой сборке 2.22 копируются только изменённые по хешу.
- После **удаления приложения** копия внутри него стирается: нужен импорт заново (2.3).
- После E1-12b: Настройки → Приложения → ME1 Mobile → «Разрешения» — **нет** «Доступ ко всем файлам».
- Загрузка файлов **без системного выбора папки** (adb или MTP прямо в папку приложения) — отдельный необязательный шаг 2.11.

**Что сделать:** «Проверить файлы» один раз, скриншот; посмотреть «Разрешения», скриншот.

**Если не так:** скриншоты, 1.14.

### 2.10 Папка с именами в другом регистре (второй импорт)

Зачем: Windows не различает `ini.big` и `INI.big`, а Android различает. Импорт должен находить файлы **без учёта регистра** букв в именах файлов и папок. Заодно это второй импорт — в нём проверяется вторая ветка 2.4а.

**Что сделать:**
1. **Сначала отчёт:** «Отправить отчёт» (1.14) — следующий шаг стирает логи приложения.
2. Сотрите импортированную копию: Настройки → Приложения → ME1 Mobile → «Хранилище и кеш» → «**Очистить хранилище**» → «ОК». Папку `Download/BFME1` это **не** трогает.
3. Уведомления — **наоборот**, чем в первом импорте: Настройки → Приложения → ME1 Mobile → «Уведомления» → переключатель «Все уведомления ME1 Mobile» **выключить** (если в 2.3 вы разрешили) или **включить** (если отклонили). Если при импорте Android снова спросит про уведомления — ответьте так же.
4. Сделайте **копию** с другим регистром имён, **оригинал не меняйте**:
   - **На ПК (основной способ):** в Проводнике скопируйте папку `C:\BFME1` на Рабочий стол (Ctrl+C → Ctrl+V) и назовите копию `BFME1-case`. **Только в копии** переименуйте (F2): `ini.big` → `INI.big`, `maps.big` → `Maps.BIG`, `_patch222.big` → `_PATCH222.big`; если копируете полный набор — ещё папку `lang` → `Lang` и в ней `english.big` → `English.big`. Для тестового набора Форматов достаточно скопировать в `BFME1-case` только его 7 файлов (2.1). Перенесите **содержимое** `BFME1-case` на телефон в `Download/BFME1-case` (как в 2.2).
   - **Без ПК** (нужно ещё столько же свободного места): в приложении «Файлы» долгое нажатие на папку `Download/BFME1` → ⋮ → «Копировать в» → `Download`; переименуйте копию в `BFME1-case` и **в ней** переименуйте файлы, как выше.
5. Запустите ME1 Mobile → «Выбрать папку с игрой» → `Download` → `BFME1-case` → «Использовать эту папку» → «Разрешить» → импорт. Во время копирования пройдите шаги 1–5 из 2.4а (вторая ветка).

**Ожидаемо:** предпроверка **зелёная**, как с исходной папкой: нет «не хватает файлов» про `ini.big`, `maps.big`, `_patch222.big`, `lang/english.big`; итог «Готово, версия 2.22v7.0.5, N файлов проверено» с тем же N, что в 2.4; «Запустить игру» доходит до того же места, что в 2.7. Плюс ожидаемое по второй ветке 2.4а.

**Если не так:** красный или жёлтый итог с упоминанием переименованных файлов — скриншот списка, 1.14 (**major**: регистр имён не должен мешать импорту). Копию `BFME1-case` не удаляйте до ответа QA.

### 2.11 Файлы без системного выбора папки: adb или MTP → «Проверить файлы» (необязательно)

Зачем: запасной путь, если системный выбор папки не сработал. Файлы кладутся прямо в папку приложения, а приложение проверяет их хеши. **adb не обязателен:** если его нет, используйте MTP (кабель + Проводник); если ПК не показывает папку приложения — ⏭.

**Что сделать:**
1. «Отправить отчёт» (1.14), затем «Очистить хранилище» (как в 2.10, шаг 2). Запустите ME1 Mobile один раз и закройте — Android создаст папку приложения.
2. Положите **содержимое** папки игры (полный набор или тестовый набор Форматов; так, чтобы `ini.big` лежал прямо в `GameData`) в `Android/data/io.github.katotekiru.me1mobile/files/GameData`. Один из вариантов:
   - **adb** (если он у вас уже есть; на телефоне включена «Отладка по USB»), в PowerShell или cmd на ПК:
     ```
     adb push <dir>/. /sdcard/Android/data/io.github.katotekiru.me1mobile/files/GameData/
     ```
     где `<dir>` — ваша папка игры, например `adb push C:/BFME1/. /sdcard/Android/data/io.github.katotekiru.me1mobile/files/GameData/`. В конце adb пишет `… files pushed` без `error`.
   - **MTP** (без adb): кабель → «Передача файлов» (1.3) → в Проводнике «Pixel 8 Pro» → «Внутренний общий накопитель» → `Android` → `data` → `io.github.katotekiru.me1mobile` → `files` → создайте папку `GameData` (если её нет) → скопируйте в неё содержимое `C:\BFME1`. Если Проводник не показывает `io.github.katotekiru.me1mobile` или не даёт копировать — ⏭, запишите это в отчёт (полезно Платформе).
3. Откройте ME1 Mobile → «**Проверить файлы**». Дождитесь конца проверки: это полный пересчёт SHA-256 (тестовый набор — минуты, полный — дольше).
4. «Запустить игру».

**Ожидаемо:** итог проверки «**Готово**, версия 2.22v7.0.5, N файлов проверено» (N — как в 2.4); «Запустить игру» доходит до того же места, что в 2.7, без выбора папки и без копирования.

⚠ «Проверить файлы» для файлов, положенных без импорта, — **ещё не реализовано — уточнить при APK с E1-12a** (где кнопка на экране).

**Если не так:** «не хватает файлов», хотя файлы на месте; итог без «Готово»; вылет — скриншот, 1.14. Ошибка adb (`Permission denied`, `No such file or directory`) — скопируйте её текст в отчёт.

### 2.12 Уборка
Только после того, как QA подтвердит отчёт по Части 2: можно удалить `Download/BFME1` и `Download/BFME1-case` (кнопкой «Удалить исходную папку» или «Файлами») и копию `BFME1-case` на ПК. Копия внутри приложения останется.

## 4. Что QA проверяет в логе (для команды, не для Андрея)

Входные данные: `bfme-report_*.zip` (основной) / запасной zip логов форка, скриншоты, отчёт Андрея; артефакты ручной сборки на боксе (`tools/build-apk.sh`, sha256 от Оркестратора) или CI. Отчёты и скриншоты — в `/workspace/bfme-mobile/qa-artifacts/`, в git только текст (`tests/reports/`). Классы — по `TEST-PLAN.md` §3.3 (ярус 0).

### 4.0 Блокер: нет UpdateManager / MYSOREZ / GeneralsOnline в APK
Критерий приёмки (Лид): в APK **нет** строк `MYSOREZ`, `raw.githubusercontent`, URL/упоминаний GeneralsOnline (и связанного remote GXRemoteConfig load). Без вырезания APK #1 Андрею не отдаём.

Команда для QA (на боксе, по файлу APK):

```bash
APK=bfme-zh-XXXXXXX.apk
TMP=$(mktemp -d)
unzip -q -o "$APK" -d "$TMP" 'classes*.dex' 'lib/**/*.so'
# ожидаем пустой вывод (нет совпадений):
strings "$TMP"/classes*.dex "$TMP"/lib/*/*.so 2>/dev/null \
  | grep -E 'MYSOREZ|raw\.githubusercontent|GeneralsOnline' || true
rm -rf "$TMP"
```

Любое совпадение = **блокер**, сборку не отдаём Андрею.

### 4.1 Сборка: коммит, sha256, versionName
- sha256 от Андрея = строке из `bfme-zh-<sha>.apk.sha256`; `<sha>` в имени = коммит сборки (`git rev-parse --short HEAD` в `tools/build-apk.sh`).
- **`applicationId`:** `io.github.katotekiru.me1mobile`; **`versionName`:** `0.1.0-<sha7>` — должен совпасть с именем APK (шаг 1.10 Андрея).
- Подпись: наш ключ (не debug-ключ форка); `apksigner` — v2/v3; отпечаток совпадает с записанным для тестовых сборок.
- В `crash.log` / баннере сборки: build id / CI run (у ручной сборки на боксе CI run = 0). Build id сверяем с `llvm-readelf -n lib/arm64-v8a/libmain.so`; символы — рядом с APK / артефактом.

### 4.2 GPU, драйвер, native smoke (без EA)
- Скриншот лаунчера 1.10 («Ваш GPU: …»), если карточка есть.
- **Native smoke (1.16):** в отчёте / логе — устройство, GPU (`GL_RENDERER` / аналог), драйвер, surface; штатный выход без сигнала краша. Нет `UnsatisfiedLinkError` / `dlopen failed` / FATAL SDL/EGL.
- Путь рендера при полном запуске с данными (Часть 2): `[d3d8gles] …` / GLES по умолчанию (`ADR-0002` §3). Vulkan/ANGLE только по выбору.

### 4.3 Ошибки инициализации SDL / EGL / Vulkan
`FATAL: Failed to initialize SDL3`, `FATAL: Failed to create SDL3 window`, `[d3d8gles] FATAL: SDL_GL_CreateContext failed`, `[d3d8gles] FATAL: SDL_GL_MakeCurrent failed`, `[d3d8gles] FATAL: could not resolve any GLES implementation`, `[d3d8gles] program link FAILED`, `FATAL: Unhandled exception in main()`, окно «Technical Difficulties». На эталоне = **блокер**. Отдельно: `MAGENTA` / `DXT upload error` / `EMPTY upload` — кандидаты в артефакт рендера (блокер на Mali), сверка со скриншотами.

### 4.4 FPCR / fast-math
- В рантайме маркеров FPCR пока может не быть (план `docs/fpcr-audit.md`).
- В журнале сборки: R4 `tools/ci/check-fp-flags.sh`, T5 `tools/fpcr/fpcr_check.py` против baseline. Нет этих строк / FAIL — APK не принимаем.

### 4.5 16 КБ, линкер, DT_NEEDED
- Журнал сборки: блок «проверка 16 КБ» — все `ok`, `WARN` только по `BFME_RELRO_WAIVE`; `zipalign` OK; DT_NEEDED `libmain.so` без «НЕТ В APK».
- На телефоне страница 4 КБ (режим 16 КБ не проверяем, Э0-6).
- Рантайм: `dlopen failed`, `UnsatisfiedLinkError`, `has text relocations` — ловим через native smoke (1.16) и отчёт, не через adb.

### 4.6 SAF, права, хеш VFS
- SAF: `SecurityException`, `Permission Denial`, ошибки `takePersistableUriPermission`, `ENOSPC`, обрыв на файле N из M, повторное копирование уже проверенных после возобновления / «Отмена».
- Итог импорта: N файлов и SHA-256 = манифест E1-24 / тестовый E1-12a; профиль версии = **2.22 v7.0.5**; при совпадении хешей **нет** «модифицированная копия»; `import-state.json` и лог импорта в `getExternalFilesDir(null)/` рядом с `GameData/`, лог — в `bfme-report_*.zip`.
- **Хеш VFS** (load-run): список смонтированных файлов совпадает с манифестом; порядок BFME1 → 2.22 → `MobileLayer/` (E1-21b).
- **Старт FGS при любом ответе на уведомления (2.4а):** в логе импорта (тег `BfmeImport`) `POST_NOTIFICATIONS granted=true` / `granted=false`, затем импорт идёт в `GameDataImportService` (`startForeground`, тип `dataSync`) и `import finished success=true` — в **обеих** ветках. Строк `refusing FGS without POST_NOTIFICATIONS` и `local import finished` быть не должно (дефект). Отдельной строки о старте FGS в PR #22 пока нет — попросить Android-разработчика (например `FGS started type=dataSync notifications=<granted>`). Со стороны устройства подтверждение — скриншоты «Активных приложений».
- **Регистр имён (2.10):** для `BFME1-case` `SAF tree listed N files` с тем же N, что для `BFME1`; на каждый файл манифеста `imported <путь из манифеста> (… sha ok)`; в предпроверке нет «missing» по переименованным; в `import-state.json` пути — как в манифесте; движок находит архивы (хеш VFS как выше). На 09.10 PR #22 (`b2fae09`) сопоставляет пути SAF с манифестом **с учётом** регистра (`SafTreeWalker` кладёт имя как есть, поиск `treeFiles.get(e.path)`) — на этой версии 2.10 даст красный итог; нужна правка до APK с E1-12a.
- **Шрифты (2.7а):** скриншот главного меню — все надписи читаются. В логе: `[fontfallback] <путь> face N family=…` (какие запасные шрифты нашлись); `[fontfallback] no fallback face found for font=…` и `[font] no glyph for U+XXXX` для латиницы и кириллицы (U+0020–U+007E, U+0400–U+04FF) — **дефект**. Строки «основной шрифт загружен» (`Create_Freetype_Font`) в логе нет — при пустых надписях без этих строк просить Платформу добавить маркер.
- **adb/MTP (2.11):** после «Проверить файлы» — `import-state.json` со `status: complete` и `GameData ready: profile=…, files checked=N`.

### 4.7 Падения, ANR, OOM; crash-selftest
- `crash.log` / AEI / tombstone (E1-15): сигнал, PC/LR, бэктрейс → символизация тем же build id.
- **Crash-selftest (1.15):** автопредложение после краша; zip с причиной; без EA.
- Падение, после которого отчёта нет, — **блокер** (§3.3). На эталоне: падение / ANR / зависание ≥ 5 с / потеря GPU / OOM на переднем плане — **блокер**.

### 4.8 Темп кадров и логики
- В промежуточном APK **нет** E1-13 / E1-14 / E1-35 — плавность в Части 1 **не оцениваем**.
- До E1-35 в игре с данными 2.22 темп может быть ≈ на 27 % быстрее нормы (`FramesPerSecondLimit = 38`) — замеры по wall-clock **предварительные** (`TEST-PLAN.md` §5.4.1).

### 4.9 Данные EA вне хранилища приложения
- После E1-12a движок читает **только** `getExternalFilesDir(null)/GameData/` пакета `io.github.katotekiru.me1mobile`.
- До E1-12b: если Андрей видел/выдавал «Доступ ко всем файлам» — отметить в отчёте (шаг 1.9).
- Состав zip: белый список (`TEST-PLAN.md` §6.6), без `.big/.w3d/.dds/…`.
- Сетевые обращения к MYSOREZ / raw.githubusercontent / GeneralsOnline — **запрещены** (см. §4.0); трафик Андрея в 1.7 ~0.

## 5. Вопросы к Android-платформе (статус)

Все 10 вопросов из v1.0 **отвечены** (Лид + Платформа). Кратко:

1. **E1-15 / логи в первом APK.** → Есть «Отправить отчёт» (`bfme-report_*.zip`, FileProvider, галочки, «Сохранить в файл», автопредложение); «Поделиться» форка — запасной путь; crash-selftest + native smoke без EA.
2. **UpdateManager / GO / GXRemoteConfig.** → Блокер: вырезаются в E1-04; без этого APK #1 не отдаём; приёмка — §1.7 и §4.0 (`strings` по dex/so).
3. **Пакет, имя, версия.** → `io.github.katotekiru.me1mobile`, имя черновик «ME1 Mobile», `versionName 0.1.0-<sha7>`, свой ключ; с форком не конфликтует.
4. **Первый запуск / «Запустить игру» без данных.** → Лаунчер без краша; диалог «Нужны файлы игры» или disabled+текст; native не грузится; полный экран «Нужны файлы BFME1» — с E1-12a.
5. **E1-12a UX (черновик).** → Кнопки «Выбрать папку с игрой», «Как скопировать с ПК», «Логи»; «Отмена» сохраняет частичное и резюмит; `POST_NOTIFICATIONS` запрашивается до копирования, но для FGS **не обязателен**: импорт всегда идёт в foreground-сервисе (`dataSync`, `stopWithTask=false`); при отказе нет уведомления в шторке, FGS виден в «Активных приложениях», импорт продолжается после сворачивания и смахивания из недавних (2.4а, обе ветки; решение Лида, правка в PR #22); файлы ищутся без учёта регистра (2.10); мало места: красный pre-check / стоп mid-copy; `import-state.json` + лог импорта рядом с GameData/, лог в отчёте; Formats test set ~665 МБ ≈ 3–10 мин на Pixel 8 Pro.
6. **E1-24 / версия данных.** → У Андрея **2.22 v7.0.5** (не v5.5.4); при совпадении хешей нет «модифицированная копия»; `.exe/.dll` не нужны; точный список — Форматы; тест E1-12a = ini+maps + 5×`_patch222*`.
7. **E1-12b.** → `MANAGE_EXTERNAL_STORAGE` / `requestLegacyExternalStorage` уходят после E1-12a; до этого не выдавать «Доступ ко всем файлам», факт выдачи — в отчёт.
8. **MTP fallback.** → Необязательный шаг 2.11: adb (`adb push <dir>/. /sdcard/Android/data/io.github.katotekiru.me1mobile/files/GameData/`) или MTP в ту же папку → «Проверить файлы» → «Готово»; не блокер; на Pixel Платформой **не проверен**.
9. **`allowBackup`.** → Для тестовых сборок `allowBackup="false"`; после переустановки настройки и путь к данным не возвращаются (шаг 1.17).
10. **Как придёт APK / состав.** → Промежуточный: E1-04 + E1-15 + вырезание обновлений/GO, ручная сборка `tools/build-apk.sh` на боксе, sha256 через Оркестратора; **без** E1-13 / E1-14 / E1-35 — ожиданий плавности в Части 1 нет.
