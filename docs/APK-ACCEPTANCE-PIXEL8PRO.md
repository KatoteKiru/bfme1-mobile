## 0. Как пользоваться чек-листом

1. Шаги идут по порядку. У каждого шага три строки: **Что сделать**, **Ожидаемо**, **Если не так**.
2. **Общее правило «если не так»:**
   - сделайте скриншот (кнопка питания + громкость вниз) или запись экрана (шторка → «Запись экрана»);
   - запишите номер шага и что увидели, в шаблон из раздела 3;
   - если приложение живо, переходите к следующему шагу; если оно закрылось само («Приложение остановлено», чёрный экран, вылет на рабочий стол), повторите шаг ещё 2 раза, затем сделайте шаг 1.14 «Поделиться логом» и пришлите всё Оркестратору.
3. **Ничего специального не нужно:** ни режима разработчика, ни разблокировки загрузчика, ни root, ни adb. adb — только как необязательная альтернатива, если он у вас уже есть (не утверждённое требование, `TEST-PLAN.md` §1 п. 2).
4. **Файлы игры EA** берутся только из вашей собственной установки BFME1 2.22. Никуда их не отправляйте и не выкладывайте: ни в облако, ни в мессенджер, ни в GitHub. Скриншоты из игры отправляйте только Оркестратору (в них графика EA, `TEST-PLAN.md` §6.6).
5. **Время:** Часть 1 — около 30 минут. Часть 2 — около 60 минут, из них 10–20 минут на копирование файлов **[оценка]**.

### 0.1 Что сейчас в коде (чтобы не удивляться)
- Лаунчер пока **унаследован от порта Zero Hour (форк MYSOREZ)**: значок и название **«GeneralsZH»**, вверху экрана «Command & Conquer Generals: Zero Hour», версия **1.3.0** на вкладке «Справка». Это ожидаемо, переименования в бэклоге Э1 нет (вопрос 5.3).
- **Без файлов игры движок не запускается совсем:** кнопка «Запустить игру» сразу возвращает в лаунчер (`GeneralsZHActivity.onCreate` перенаправляет в Setup и не загружает `libmain.so`). Поэтому в Части 1 логов движка не будет: это ожидаемо.
- Экрана «Нужны файлы BFME1», SAF-импорта и кнопки «Отправить отчёт» на `e9292c9` нет (E1-12a, E1-15). Есть только просмотр логов форка с кнопкой «Поделиться».
- Движок на `e9292c9` ещё не читает архивы BFME1 (формат `BIG4`: E1-21 на ревью в PR #2, подключение в игре — E1-21b). **Часть 2 имеет смысл только с APK, где Платформа подтвердит E1-12a и чтение данных BFME1.**

## Часть 1. Запуск и логи (без данных игры)

### 1.1 Что вы получите

**Что сделать:** взять у Оркестратора два файла (или zip-артефакт CI `bfme-zh-apk-<номер запуска>.zip`, внутри те же два файла):
- `bfme-zh-<7 символов коммита>.apk` — само приложение, около **40–45 МБ** (прошлые сборки: 43,5 МБ);
- `bfme-zh-<коммит>.apk.sha256` — текстовый файл из одной строки: 64 символа контрольной суммы, два пробела, имя APK. Например: `5ef54c11…f293457  bfme-zh-d1079b0.apk`.

**Ожидаемо:** имена обоих файлов содержат один и тот же код коммита. Его же запишите в отчёт.

**Если не так:** нет файла `.sha256` или коды в именах разные — не устанавливайте, напишите Оркестратору.

### 1.2 Проверка sha256
Сумма доказывает, что вы ставите ровно тот файл, который собрал CI (сборка `tools/build-apk.sh` пишет `.sha256` сразу после проверки подписи).

**Что сделать (основной путь — ПК с Windows):**
1. Положите оба файла в одну папку, например «Загрузки».
2. Откройте PowerShell (Пуск → набрать «PowerShell») и выполните, подставив своё имя файла:
   ```
   Get-FileHash "$env:USERPROFILE\Downloads\bfme-zh-XXXXXXX.apk" -Algorithm SHA256
   ```
   Вариант без PowerShell (командная строка `cmd`): `certutil -hashfile "%USERPROFILE%\Downloads\bfme-zh-XXXXXXX.apk" SHA256`.
3. Откройте `.sha256` в Блокноте и сравните **все 64 символа**. Регистр не важен: PowerShell печатает заглавными, файл — строчными.
   - На macOS: `shasum -a 256 bfme-zh-XXXXXXX.apk`; на Linux: `sha256sum -c bfme-zh-XXXXXXX.apk.sha256` (должно быть `OK`).

**На телефоне (необязательно):** встроенной проверки суммы на Pixel нет. Если APK скачан прямо на телефон, можно проверить его любым приложением подсчёта хешей, которому вы доверяете; если такого нет, перешлите тот же файл на ПК и проверьте там.

**Ожидаемо:** суммы совпадают полностью.

**Если не так:** **не устанавливайте.** Скачайте файл заново; если сумма снова другая, сообщите Оркестратору оба значения.

### 1.3 Перенос APK на телефон

**Что сделать (один из вариантов):**
- **Кабель USB-C:** подключите телефон к ПК → на телефоне в уведомлении «Зарядка через USB» нажмите → выберите «Передача файлов». На ПК в Проводнике откройте «Pixel 8 Pro» → «Внутренний общий накопитель» → `Download` и скопируйте туда APK.
- **Прямо на телефоне:** скачайте APK из того же чата, где его прислали. Chrome может предупредить «Файл может быть опасен» — выберите «Всё равно скачать».

**Ожидаемо:** в приложении «Файлы» → «Загрузки» виден `bfme-zh-….apk` того же размера.

**Если не так:** размер другой или файл не открывается — скачайте ещё раз и повторите 1.2.

### 1.4 Установка

**Что сделать:**
1. «Файлы» → «Загрузки» → нажмите на `bfme-zh-….apk`.
2. Android скажет, что установка неизвестных приложений из этого источника запрещена → «Настройки» → включите «Разрешить установку из этого источника» → «Назад». (Если ставите из Chrome или Telegram, разрешение спросят для этого приложения.)
3. «Установить».
4. **Play Protect** может показать «Приложение заблокировано» / «Play Protect не знает этого разработчика» (APK подписан нашим отладочным ключом `CN=BFME1 Mobile Debug`, не из Google Play). Нажмите «Подробнее» → «Всё равно установить». Если предложит «Отправить приложение на проверку» — «Не отправлять» (репозиторий приватный).
5. «Готово» (не «Открыть»: перед первым запуском нужен шаг 1.6).

**Ожидаемо:** установка завершается за 10–30 секунд; на рабочем столе и в списке приложений появляется **один** значок **«GeneralsZH»**.

**Если не так:**
- «Приложение не установлено» / «пакет конфликтует с существующим»: на телефоне уже стоит приложение с тем же именем пакета `com.generalsx.zerohour`, но с другой подписью (например, оригинальный GeneralsZH из форка или наша сборка со старым ключом). Пришлите скриншот; дальше по 1.15 (удалить старое, предварительно отправив логи).
- «Пакет повреждён» / «Ошибка синтаксического анализа»: файл испорчен, вернитесь к 1.2.
- Play Protect не даёт кнопки «Всё равно установить» (только «ОК»): остановитесь, скриншот Оркестратору.

> **Альтернатива для тех, у кого уже есть adb (необязательно):** на телефоне включена «Отладка по USB», на ПК: `adb install -r bfme-zh-XXXXXXX.apk` → ответ `Success`. Логи через `adb logcat` можно приложить, но приёмка на них не опирается.

### 1.5 Данные устройства (записать один раз перед стартом)
Перенесите в раздел «Устройство» отчёта (шаблон в разделе 3).

| Что | Где на Pixel 8 Pro |
|---|---|
| Модель | Настройки → О телефоне → «Модель» (ожидаем Pixel 8 Pro) |
| Версия Android | Настройки → О телефоне → «Версия Android» (нажать) → «Версия Android» |
| Патч безопасности | там же → «Обновление системы безопасности» (дата) |
| Номер сборки | Настройки → О телефоне → «Номер сборки» (самая нижняя строка, например `BP2A.…`) |
| Батарея | Настройки → Батарея: заряд в %, на зарядке или нет, включено ли «Энергосбережение»; «Состояние батареи», если такой пункт есть |
| Нагрев | отдельного показателя у Android нет: запишите «холодный / тёплый / горячий на ощупь» и было ли предупреждение «Телефон нагрелся» |
| Свободное место | Настройки → Хранилище: «Использовано X ГБ из Y ГБ» → свободно Y − X |
| Экран | Настройки → Экран → «Разрешение экрана» (Высокое 2244×1008 / Максимальное 2992×1344) и «Плавный экран» вкл./выкл. |

**Условия, которые просим соблюдать (как в `TEST-PLAN.md` §5.6):** заряд ≥ 50 %, телефон не на зарядке, энергосбережение выключено, телефон не горячий.

### 1.6 Первый запуск без данных игры

**Что сделать:**
1. Включите **режим полёта** (шторка → «Режим полёта»). Зачем: лаунчер форка при каждом открытии сам проверяет обновления на сервере исходного проекта (`UpdateManager`, адрес `raw.githubusercontent.com/MYSOREZ/…/updates`), а для чистой проверки нам нужна только наша сборка (вопрос 5.2).
2. Нажмите значок «GeneralsZH».

**Ожидаемо:**
- через 1–3 секунды открывается экран лаунчера в портретной ориентации: вверху мелкими заглавными «COMMAND & CONQUER GENERALS: ZERO HOUR», под ним название вкладки «Главная», справа значок документа (логи); внизу пять вкладок — **Главная, Графика, Интерфейс, Инструменты, Справка**;
- на «Главной»: большая кнопка «Запустить игру», карточка «Папка с игрой» со строкой **«Папка с игрой: не задана.»**, кнопки «Выбрать папку с игрой», «Папка базовой Generals…», «Сбросить папку с игрой», ниже карточки GeneralsOnline и «Обновления»;
- **ни одного системного запроса разрешений** при первом запуске (в коде их нет до нажатия «Выбрать папку с игрой»);
- не закрывается, не зависает; язык лаунчера — язык телефона.

⚠ **По бэклогу** при первом запуске должен быть экран «Нужны файлы BFME1»: что нужно (своя копия 1.03 + Patch 2.22), сколько места требуется и сколько свободно, кнопки «Выбрать папку с игрой», «Как скопировать с ПК», «Логи» (`game-files-access.md` §6 п. 1, E1-12a) — **ещё не реализовано на e9292c9 — уточнить при первом APK.** Если в вашем APK он есть: проверьте, что цифры места похожи на правду (свободное место совпадает с «Хранилищем» из 1.5 ± 1 ГБ).

**Если не так:**
- «Приложение остановлено» или вылет на рабочий стол — **падение лаунчера**: повторите 2 раза, скриншоты, сразу к 1.14.
- Вместо обычного экрана текст «Обычный интерфейс настроек не загрузился (…) Показан упрощённый вариант…» — лаунчер включил запасной режим; скриншот (текст в скобках важен), дальше можно продолжать.

### 1.7 Отключить автопроверку обновлений

**Что сделать:** «Главная» → прокрутить вниз до карточки «Обновления» → выключить переключатель **«Проверять автоматически»**. Сделайте скриншот карточки. После этого режим полёта можно выключить.

**Ожидаемо:** в карточке строка вида «Движок: **встроенный**, сборка N · Последняя проверка: ещё не было».

**Если не так:**
- «Движок: **обновлённый**, сборка …» — **стоп**, дальше не продолжайте: игра запускала бы чужой движок, а не нашу сборку. Скриншот Оркестратору (для QA это блокер).
- Всплывающее сообщение «Новому движку (сборка …) нужен новый APK» или «Вышла новая версия сетевых данных игры» — это сервер исходного проекта, не наш; запишите в отчёт, продолжайте.

### 1.8 «Запустить игру» без данных

**Что сделать:** «Главная» → «Запустить игру». Повторите 3 раза.

**Ожидаемо:** экран может на мгновение повернуться в альбомную ориентацию и **сразу вернуться в лаунчер** на «Главную» (в коде: игра без папки с данными не стартует и возвращает в настройки). Нет чёрного экрана дольше 5 секунд, нет «Приложение остановлено».

⚠ По бэклогу здесь ожидается переход к экрану «Нужны файлы BFME1» или к SAF-импорту (E1-12a) — **ещё не реализовано на e9292c9 — уточнить при первом APK.**

**Если не так:** чёрный экран > 5 с, зависание, вылет — скриншот или запись экрана, затем 1.14.

### 1.9 Диалоги разрешений

**Что сделать:**
1. «Главная» → «Выбрать папку с игрой».
2. Появится подсказка «Предоставьте разрешение «Доступ ко всем файлам» на следующем экране…» и откроется системный экран «Доступ ко всем файлам» для GeneralsZH.
3. **Не включайте** переключатель. Нажмите «Назад».
4. Настройки телефона → Приложения → GeneralsZH → «Разрешения»: сделайте скриншот списка.

**Ожидаемо:** после «Назад» вы снова в лаунчере, строка «Папка с игрой: не задана.», без вылета. В «Разрешениях» ничего не выдано.

**Почему не включать:** это старый путь форка (`MANAGE_EXTERNAL_STORAGE`): после выбора папки лаунчер записывает в выбранную папку свои файлы (`dxvk.conf`, `DefaultOptions.ini`, `fonts/`, `Window/`) и оставляет в корне памяти файл `.generalszh_gamepath.txt`, который переживает удаление приложения. В нашем проекте этот путь убирается (E1-12b) и заменяется SAF-импортом из Части 2.

⚠ В APK с E1-12b запроса «Доступ ко всем файлам» быть **не должно** — **ещё не реализовано на e9292c9 — уточнить при первом APK.** Если в вашем APK кнопка сразу открывает системный выбор папки — это уже Часть 2: нажмите «Назад» (отмена) и проверьте, что лаунчер не упал.

**Если не так:** вылет после «Назад» — скриншот, 1.14.

### 1.10 Видеокарта и версия (скриншоты)

**Что сделать:**
1. Вкладка «Графика»: скриншот карточки «Графический бэкенд» (строки «Ваш GPU: …» и «Сейчас: …»). **Бэкенд не меняйте.**
2. Вкладка «Справка»: скриншот (номер версии).

**Ожидаемо:** «Ваш GPU: Mali-G715…» (строка драйвера от `GL_RENDERER`), «Сейчас: OpenGL ES (по умолчанию)» (`ADR-0002` §3: GLES по умолчанию, ANGLE и Vulkan только по выбору). На «Справке» версия **1.3.0** (она одинакова у всех сборок, поэтому сборку определяем по имени APK и sha256).

**Если не так:** другой GPU или другой бэкенд по умолчанию — скриншот, продолжайте.

### 1.11 Поворот экрана

**Что сделать:** включите автоповорот (шторка → «Автоповорот»). На вкладках «Главная» и «Инструменты» поверните телефон: портрет → альбом → портрет, по 2 раза.

**Ожидаемо:** экран перестраивается за долю секунды, остаётся та же вкладка, текст не обрезан, нет пустого экрана, нет вылета.

**Если не так:** скриншот в той ориентации, где плохо.

### 1.12 Свернуть и вернуться

**Что сделать:**
1. На «Главной» сделайте жест «Домой», подождите 30 секунд, верните приложение через список недавних (свайп снизу и задержка).
2. То же с вкладки «Инструменты».
3. Заблокируйте экран кнопкой питания на 10 секунд, разблокируйте.

**Ожидаемо:** лаунчер возвращается на ту же вкладку без перезапуска и без вылета.

**Если не так:** вернулся на «Главную» вместо «Инструментов» — запишите (minor); вылет или пустой экран — скриншот, 1.14 (сбой после возврата — major по `TEST-PLAN.md` §3.1).

### 1.13 Холодный перезапуск

**Что сделать:**
1. Настройки → Приложения → GeneralsZH → «Остановить» → «ОК». Запустите значок снова.
2. Перезагрузите телефон, после загрузки запустите приложение (это «холодный старт» по `TEST-PLAN.md` §5.2).

**Ожидаемо:** оба раза лаунчер открывается за 1–3 секунды на «Главной»; переключатель «Проверять автоматически» остался выключенным; «Папка с игрой: не задана.».

**Если не так:** вылет, настройки сбросились — скриншот, 1.14.

### 1.14 «Поделиться логом»

**Что сделать:**
1. Вкладка «Инструменты» → «Просмотреть логи» (то же открывает значок документа в правом верхнем углу любой вкладки).
2. Сделайте скриншот экрана логов (прокрутите, если длинный).
3. Нажмите «**Поделиться**». Если откроется меню «Поделиться логом», выберите чат с Оркестратором (Telegram, почта и т. п.) и отправьте файл **`generalszh-logs.zip`**.
4. Кнопку «Очистить логи» **не нажимайте**.

**Ожидаемо в Части 1 (код `e9292c9`):** все четыре раздела показывают «(отсутствует — …)», потому что движок ни разу не запускался; на «Поделиться» появляется сообщение **«Файлы логов пока не найдены.»** — это правильно. Тогда пришлите скриншоты из п. 2. Если игра падала, в zip будут `crash.log`, `crash-prev.log`, `generals-stderr.log`, `generals-stderr-prev.log`.

⚠ **По бэклогу (E1-15, `TEST-PLAN.md` §6.4–6.5)** должна быть кнопка «**Отправить отчёт**» в лаунчере и в меню паузы, перед отправкой список файлов с галочками, файл `bfme-report_<версия>_<причина>_<дата-время>_<сессия>.zip`, вариант «Сохранить в файл» и автопредложение после аварийного выхода («Прошлый запуск завершился с ошибкой. Отправить отчёт?») — **ещё не реализовано на e9292c9 — уточнить при первом APK.** Если она есть, используйте её вместо «Поделиться».

**Куда отправлять:** только Оркестратору, в тот же чат, откуда пришёл APK. Не в GitHub и не в открытые чаты.

**Если не так:** «Не удалось подготовить файл лога для отправки: …» — скриншот с текстом ошибки.

### 1.15 Удаление и переустановка

**Что нужно знать:**
- **Сначала логи, потом удаление.** Удаление стирает всё приложение: логи (`crash.log`, `generals-stderr.log`), настройки и (после E1-12a) импортированную копию игры в `Android/data/com.generalsx.zerohour/files/GameData` — тогда понадобится повторный импорт.
- **Новая сборка поверх старой** ставится как обычно (1.4), данные сохраняются. Номер версии у всех сборок сейчас один (1.3.0, versionCode 10300), Android это допускает.
- «Приложение не установлено» при установке поверх — другая подпись: отправьте логи (1.14), удалите приложение, поставьте заново.
- Если вы когда-либо выдавали «Доступ ко всем файлам» и выбирали папку, файл `.generalszh_gamepath.txt` в корне памяти телефона после удаления остаётся; новая установка может сама «вспомнить» папку. Напишите об этом в отчёте.
- В приложении включена резервная копия Android (`allowBackup`), поэтому после переустановки настройки могут восстановиться из копии Google.

**Проверка (в конце Части 1, ≈ 3 мин):** 1.14 → удалить (долгое нажатие на значок → «Удалить», или Настройки → Приложения → GeneralsZH → «Удалить») → поставить тот же APK (1.4) → запустить.

**Ожидаемо:** чистое состояние: «Папка с игрой: не задана.», «Последняя проверка: ещё не было» (или восстановленные настройки — тогда просто запишите это).

**Если не так:** вылет после переустановки — скриншот, 1.14.

## Часть 2. SAF-импорт данных игры

> ⚠ **Вся Часть 2 — ещё не реализовано на e9292c9 — уточнить при первом APK** (E1-12a SAF-импорт, E1-24 манифест, E1-12b, E1-21/E1-21b чтение архивов BFME1). Ожидаемое поведение ниже взято из `game-files-access.md` §6 и критериев E1-12a. Начинайте Часть 2, только когда Оркестратор скажет, что APK это умеет. Названия кнопок могут отличаться: ориентируйтесь на смысл и фотографируйте каждый новый экран.

### 2.1 Какие файлы взять с ПК

**Что сделать:**
1. На своём ПК откройте папку установки BFME1 с Patch 2.22 (у вас это `C:\BFME1`; в главном меню игры в углу строка «Patch 2.22v7.0.5»).
2. Проверьте, что в ней прямо в корне лежат архивы `.big`: `ini.big`, `maps.big`, `w3d.big`, `textures.big`, `terrain.big`, `audio.big`, `music.big`, `ambientstreams.big`, `shaders.big` и пять файлов патча `_patch222.big`, `_patch222bases.big`, `_patch222libraries.big`, `_patch222maps.big`, `_patch222textures.big`; рядом папки `lang` (там `englishaudio.big` и другие языковые архивы), `apt`, `data`.
3. **Копируйте папку целиком.** По замеру вашей копии это **351 файл, 3 852 776 700 байт ≈ 3,6 ГиБ** (`DATA-VERSION.md`, `gamedata/COPY_LOG.md`), из них архивы `.big` ≈ 2,6 ГБ. Программы (`lotrbfme.exe`, `worldbuilder.exe`, `*.dll`) игре на телефоне не нужны, но мешать не будут; точный список обязательных файлов даст манифест E1-24 (вопрос 5.6).

**Важно:** только ваша собственная легальная копия. Не скачивайте игру или патч из интернета, не берите чужую папку, не загружайте файлы в облако, мессенджер или на GitHub — только кабелем на свой телефон.

**Если не так:** нет `_patch222*.big` — патч 2.22 не установлен; остановитесь и напишите Оркестратору.

### 2.2 Перенос папки на телефон

**Что сделать:**
1. Проверьте свободное место (Настройки → Хранилище): нужно **не меньше 8 ГБ** — копия в «Загрузках» (≈ 3,6 ГиБ) плюс копия внутри приложения (≈ 3,6 ГиБ) плюс ~10 % запаса (`game-files-access.md` §3).
2. Подключите кабель, выберите «Передача файлов» (как в 1.3).
3. В Проводнике: «Pixel 8 Pro» → «Внутренний общий накопитель» → `Download` → создайте папку **`BFME1`** → скопируйте в неё **содержимое** `C:\BFME1` (чтобы `ini.big` лежал прямо в `Download\BFME1`, а не в `Download\BFME1\BFME1`). Подойдёт и `Documents\BFME1`.
4. Не кладите файлы прямо в `Download` без подпапки и не пытайтесь положить в `Android/data`: системный выбор папки не даёт выбрать корень `Download` и `Android/data` (ограничение Android 11+).

**Ожидаемо:** копирование 3,6 ГиБ по кабелю занимает **3–15 минут [оценка]**; в «Файлах» на телефоне в `Download/BFME1` видны те же файлы, общий размер ≈ 3,6 ГиБ.

**Если не так:** Windows пишет об ошибке копирования или размер другой — скопируйте папку заново; сфотографируйте ошибку.

### 2.3 Импорт через системный выбор папки (SAF)

**Что сделать:**
1. Запустите приложение. Ожидается экран «Нужны файлы BFME1» (1.6) с объёмом «нужно / свободно» → «**Выбрать папку с игрой**».
2. Откроется **системный** экран выбора папки (похож на приложение «Файлы»). Меню ☰ → «Pixel 8 Pro» → `Download` → `BFME1` → внизу «**Использовать эту папку**».
3. Android спросит примерно «Разрешить приложению GeneralsZH доступ к файлам в папке BFME1?» → «**Разрешить**».

**Ожидаемо (`game-files-access.md` §6 п. 2–3, E1-12a):**
- никакого «Доступ ко всем файлам» (после E1-12b его нет совсем);
- сразу **предпроверка** за несколько секунд, без копирования: список файлов и размеры сверяются с манифестом, проверяется место. Итог одним из цветов: **зелёный** («версия 2.22 v7.0.5», можно продолжать), **жёлтый** («модифицированная копия» или «нет 2.22» — предупреждение, решаете вы), **красный** («не хватает файлов: …» — импорт не начнётся);
- кнопка начала импорта (название уточнить).

**Если не так:** красный итог с вашей полной папкой, жёлтый «модифицированная копия» с чистой 2.22 (вероятно, манифест сделан под другую сборку 2.22, вопрос 5.6), вылет после «Разрешить» — скриншоты, 1.14.

### 2.4 Прогресс, время, размер

**Ожидаемо:**
- экран прогресса: сколько МБ скопировано из скольких, скорость, оставшееся время; одновременно уведомление в шторке (импорт идёт в foreground-сервисе `dataSync`, E1-12a). Если Android спросит разрешение на уведомления — «Разрешить»;
- **экран можно выключить**, импорт продолжится;
- объём ≈ **3,6 ГиБ** (или меньше, если манифест исключает программы); время на Pixel 8 Pro **2–10 минут [оценка, не замерено]** — копирование и SHA-256 идут одним проходом;
- итог: «**Готово, версия 2.22v7.0.5, N файлов проверено**» и кнопки «Играть» и «Удалить исходную папку».
- **Не удаляйте исходную папку**, пока не пройдёте 2.7–2.8 и QA не подтвердит отчёт.

**Если не так:** прогресс стоит на месте больше 30 секунд, время больше 20 минут, итог «N файлов» без слова «проверено» или с ошибками — запись экрана, 1.14. Запишите фактическое время от начала до «Готово».

### 2.5 Отмена и прерывание

**Что сделать (по одному разу, в любом порядке):**
1. Во время импорта нажмите «Отмена» (если есть) → снова запустите импорт.
2. Во время импорта смахните приложение из списка недавних → откройте снова.
3. Во время импорта выключите экран на 1 минуту → включите.

**Ожидаемо:** после 1–2 импорт **продолжается с места остановки** (уже проверенные файлы не копируются заново, прогресс не с нуля); после 3 он не прерывался. В итоге то же «N файлов проверено», что и без прерываний. Никаких вылетов (E1-12a: «прерывание (выключили экран или убили процесс) возобновляется»).

**Если не так:** импорт начался с нуля — запишите (major); после продолжения игра не стартует или пишет о повреждённых файлах — **порча данных, блокер** (`TEST-PLAN.md` §3.3): не удаляйте ничего, 1.14.

### 2.6 Мало места
Специально забивать память **не нужно**. Проверяйте, только если места и правда мало.

**Ожидаемо:** предпроверка (2.3) говорит «нужно X ГБ, свободно Y ГБ» и **не начинает** копирование. Если место кончилось во время импорта (например, параллельно скачивалось что-то большое): понятное сообщение об ошибке, без вылета; после освобождения места импорт продолжается с места остановки.

**Если не так:** вылет, «зависший» прогресс без сообщения, импорт «успешен» при нехватке места — скриншоты, 1.14 (ошибка импорта даже с понятным сообщением на эталоне — major, `TEST-PLAN.md` §3.3).

### 2.7 Второй запуск — до главного меню

**Что сделать:** закройте приложение (смахнуть из недавних), запустите снова → «Запустить игру».

**Ожидаемо:** быстрая проверка без повторного копирования (E1-12a: «повторный запуск идёт сразу в игру»); игра поворачивается в альбомную ориентацию; загрузка без чёрного экрана дольше 30 секунд без движения; появляется главное меню BFME1 со строкой «Patch 2.22v7.0.5» в углу.

⚠ Главное меню BFME1 требует чтения архивов BFME1 и INI 2.22 (E1-21/E1-21b, E1-56, E1-36) — **ещё не реализовано на e9292c9 — уточнить при первом APK**, что в этой сборке считается «дошли» (меню, shellmap или только карта M2).

**Если не так:** вылет на загрузке, бесконечная загрузка (> 30 с без движения), фиолетово-розовые («магента») или чёрные текстуры — скриншот, 1.14. На Pixel 8 Pro это **блокеры** (`TEST-PLAN.md` §3.3).

### 2.8 Короткий smoke-тест (2–3 минуты игры)

**Что сделать:**
1. Главное меню → «Схватка» (Skirmish) → карта **Fords of Isen** («карта M1» из бэклога; запасная — Westfold) → любая фракция → «Начать».
2. 2–3 минуты: проведите камерой одним пальцем, приблизьте и отдалите щипком, поверните двумя пальцами, выделите своё здание или отряд.
3. Выход через меню игры («Выйти» / «Quit») → снова главное меню → выход из игры.
4. Если в APK есть счётчик FPS на экране (E1-39), сфотографируйте его один раз в середине.

**Ожидаемо:** карта загружается (цель Э1 — ≤ 30 секунд), нет вылетов, нет магенты и чёрных пятен на земле, нет «заморозок» картинки дольше 1 секунды, касания попадают куда надо; выход возвращает в меню, потом в лаунчер.

**Известное, не отдельная ошибка:** пока не влит фикс темпа E1-35, игра в схватке идёт примерно на 27 % быстрее нормы (логика ≈ 38 тиков/с вместо 30 из-за `FramesPerSecondLimit = 38` в данных 2.22, `TEST-PLAN.md` §5.4.1). AI противника и скрипты карты в Э1 отключены (E1-37), юниты и здания могут быть статичными.

⚠ Схватка BFME1 на телефоне — цель вех M2–M3 (E1-33, E1-38, E1-41) — **ещё не реализовано на e9292c9 — уточнить при первом APK.**

**Если не так:** запись экрана места проблемы, 1.14.

### 2.9 Повторный импорт и обновление

**Ожидаемо (`game-files-access.md` §4 и §6 п. 6–7):**
- **«Проверить файлы»** — полный пересчёт SHA-256 импортированной копии; итог «N файлов проверено» без ошибок.

## 4. Что QA проверяет в логе (для команды, не для Андрея)

Входные данные: `generalszh-logs.zip` / `bfme-report_*.zip`, скриншоты, отчёт Андрея; артефакты CI того же запуска (`bfme-zh-apk-<run>`, `bfme-zh-symbols-<run>` — 90 дней, `bfme-zh-build-log-<run>`). Отчёты и скриншоты — в `/workspace/bfme-mobile/qa-artifacts/`, в git только текст (`tests/reports/`). Классы — по `TEST-PLAN.md` §3.3 (ярус 0).

### 4.1 Сборка: коммит, sha256, build id
- sha256 от Андрея = строке из `bfme-zh-<sha>.apk.sha256` артефакта; `<sha>` в имени = коммит запуска CI (`git rev-parse --short HEAD` в `tools/build-apk.sh`).
- `versionName 1.3.0` / `versionCode 10300` и `assets/engine_build.txt` (`git rev-list --count` на shallow-клоне — единицы; в сборке `e29eade` было `3`) сборку **не определяют**. Git sha в лог движка не пишется (вопрос 5.3).
- В `crash.log`: `=== libmain.so loaded, crash handler installed (t=…) [build compiled <дата> <время>, CI run N, build id <hex>] ===`; в `generals-stderr.log`: `[GX-BUILD] libmain.so compiled … CI run N, build id <hex>` и баннер ` CI build number: N`. N = `github.run_number` (`BFME_BUILD_NUMBER`), у ручной сборки на боксе — 0. Build id сверяем с `llvm-readelf -n lib/arm64-v8a/libmain.so` из APK; символы — `out/symbols/libmain-<sha>.symbols.txt.gz`.
- Журнал сборки: `apksigner` — `Verified using v2/v3`, сертификат `CN=BFME1 Mobile Debug`, отпечаток совпадает с прошлыми сборками (Э0-3; иначе Андрей не сможет ставить поверх).

### 4.2 GPU, драйвер, выбранный путь рендера
- Строка драйвера сейчас есть **только** в лаунчере: «Ваш GPU: …» (`GL_RENDERER` через EGL14, скриншот 1.10). Движок не пишет `GL_VENDOR/GL_RENDERER/GL_VERSION`, EGL-конфиг и `VkPhysicalDeviceDriverProperties` (`device.json`, §6.3 TEST-PLAN — E1-15, нет на `e9292c9`).
- Путь: `[d3d8gles] render_backend.cfg resolved to: <gles|gles_angle|vulkan>`; `INFO: Using native GLES3 backend (no Vulkan)`; `[d3d8gles] GLES backend: <библиотека>` (системная `libGLESv3.so` или `libGLESv2_angle.so`); `[d3d8gles] ANGLE GLES dispatch unavailable, falling back to system libGLESv3.so` (просили ANGLE, получили системный — отметить); `[d3d8gles] Direct3DCreate8_GLES(sdk=…) - native GLES3 renderer`; `[d3d8gles] GLES3 context ready WxH (s3tc=N)` — на Mali ожидаем `s3tc=0` (DXT декодируется на CPU, ADR-0002 §8); `INFO: mobile internal resolution set to …` (масштаб, E1-13).
- Vulkan (только по выбору): `INFO: Loading Vulkan library...`, строки DXVK, `WARNING: Failed to load Vulkan`; `custom_driver.cfg`/adrenotools на Mali не должны срабатывать. Ожидаемо по умолчанию: **GLES, без Vulkan и без ANGLE**.

### 4.3 Ошибки инициализации SDL / EGL / Vulkan
`FATAL: Failed to initialize SDL3`, `FATAL: Failed to create SDL3 window`, `[d3d8gles] FATAL: SDL_GL_CreateContext failed`, `[d3d8gles] FATAL: SDL_GL_MakeCurrent failed`, `[d3d8gles] FATAL: could not resolve any GLES implementation`, `[d3d8gles] program link FAILED`, `[d3d8gles] glGetError at frame …`, `FATAL: Unhandled exception in main()`, `FATAL: Unknown exception in main()`, окно «Technical Difficulties». Любая из них на эталоне = **блокер** (падение/потеря GPU). Отдельно: `[d3d8gles] MAGENTA: texture format …`, `[d3d8gles] DXT upload error`, `[gxtex] EMPTY upload` — кандидаты в **артефакт рендера (блокер на Mali)**, сверить со скриншотами.

### 4.4 FPCR / fast-math
- В рантайме маркеров FPCR пока нет: модуль `fp::` (`checkAndReset`, `-gxFpCheck`, счётчики `tick_start_deviations`/`tick_end_failures`) — план `docs/fpcr-audit.md`, в коде на `e9292c9` отсутствует. Есть только трасса форка `fp invalid frame N: …` (FE_INVALID, не режим FPCR) в сетевой трассе при включённом `gx_net_trace`.
- Проверка — в журнале сборки: шаг R4 `tools/ci/check-fp-flags.sh` (нет `-ffast-math`/`-Ofast`/`-funsafe-math-optimizations`) и T5 `tools/fpcr/fpcr_check.py` против `tools/fpcr/fpcr-baseline.json` (новая `MSR FPCR` или импорт `fe*` валит сборку). Нет этих строк в журнале — APK не принимаем.

### 4.5 16 КБ, линкер, DT_NEEDED
- Журнал сборки: блок «проверка 16 КБ» — все `ok`, `WARN` допустим только для `libc++_shared.so`, `libEGL_angle.so`, `libGLESv2_angle.so` (`BFME_RELRO_WAIVE`), ни одного `FAIL`; `zipalign: Verification successful` (справочно); «проверка APK: DT_NEEDED libmain.so» без строк `НЕТ В APK: …`.
- На телефоне размер страницы 4 КБ (загрузчик не разблокируем, режим 16 КБ не проверяем, Э0-6).
- Рантайм: `dlopen failed`, `library "…" not found`, `UnsatisfiedLinkError`, `has text relocations`, `unsupported flags DT_FLAGS_1` — сейчас видны только в logcat (adb, необязательно) или по системному «Приложение остановлено» сразу после «Запустить игру». **В Части 1 загрузка `.so` не проверяется вовсе** (без данных `libmain.so` не грузится) — вопрос 5.1.

### 4.6 SAF, права, хеш VFS
- SAF: `SecurityException`, `Permission Denial`, `No persistable permission grants`, ошибки `takePersistableUriPermission`, `FileNotFoundException` на `content://…`, `ENOSPC` / `No space left on device`, обрыв на файле N из M, повторное копирование уже проверенных файлов после возобновления.
- Итог импорта: N файлов и суммы SHA-256 = манифест E1-24 и `gamedata/MANIFEST.sha256` на боксе (та же копия `C:\BFME1`); профиль версии = 2.22 v7.0.5; `import-state.json` записан.
- **Хеш VFS** (load-run, `TEST-PLAN.md` §5.2 п. 3): список смонтированных файлов (имя, размер, SHA-256 из манифеста) одинаков во всех прогонах и совпадает с манифестом; порядок монтирования BFME1 → 2.22 → `MobileLayer/` по `bfme1-mount-order.cfg` виден в логе (E1-21b).

### 4.7 Падения, ANR, OOM, нагрев
- `crash.log` / `crash-prev.log`: сигнал (`SIGSEGV`, `SIGBUS`, `SIGABRT`, `SIGILL`, `SIGFPE`), PC/LR, адрес, бэктрейс «библиотека + смещение» → символизация `scripts/qa/symbolize-android-crash.py` с символами того же build id. `abort()`/`DEBUG_CRASH` — сообщение перед сигналом.
- Без E1-15 **нет**: tombstone (`ApplicationExitInfo` `REASON_CRASH_NATIVE`), трасс ANR (`REASON_ANR`), признаков LMK/OOM (`REASON_LOW_MEMORY`), Java-исключений в файл, кольцевого лога, `sessions.json`, `samples.csv` с `thermal_status`. Косвенно OOM: лог обрывается без `INFO: GameMain() returned …` / `Exiting with code …` и без сигнала в `crash.log`. Падение, после которого отчёта нет, — **блокер** (§3.3).
- Классы на эталоне: падение любого типа, ANR, зависание ≥ 5 с, потеря GPU, OOM на переднем плане — **блокер**; фриз 1–5 с — major; несохранённые настройки после возврата — major.

### 4.8 Темп кадров и логики
- Логика **30 Гц** (`LOGICFRAMES_PER_SECOND`, ADR-0002 §7); рендер по умолчанию 30 FPS через Swappy (E1-14, на `e9292c9` нет).
- **До E1-35:** в одиночной игре и схватке логика тикает на каждом кадре рендера, кап рендера берётся из `FramesPerSecondLimit = 38` (`gamedata.ini` 2.22) → ≈ 38 тиков/с, игра ≈ на 27 % быстрее. Всё, что меряется по реальному времени (FPS, нагрев, время до LIGHT/MODERATE, окна прогрева), — **предварительно** (`analyze_frames.py --preliminary`, окна в кадрах логики `--logic-window 1801-10800`).
- Правило темпа (`TEST-PLAN.md` §5.4.1): (последний `logic_frame` − первый) / Δ`t_ns` = 30 ± 1, иначе прогон недействителен (код 2); нет `logic_frame` — «не проверено». Сейчас доступны только строки `[d3d8gles] perf: … fps` при включённом маркере `gx_perf.txt`.

### 4.9 Данные EA вне хранилища приложения
- Пути `/storage/emulated/0/…` вне `Android/data/com.generalsx.zerohour/` в логах и отчёте; после E1-12a движок читает **только** `getExternalFilesDir(null)/GameData/`, кэш ETC2 (если E1-27) — тоже там.
- Старый путь форка (1.9): запись `dxvk.conf`, `DefaultOptions.ini`, `fonts/`, `Window/GroupPanel.wnd` в выбранную папку пользователя и `/sdcard/.generalszh_gamepath.txt` — после E1-12b этого быть не должно; если Андрей видел «Доступ ко всем файлам» или выбирал папку — отметить.
- Состав zip: только белый список (`TEST-PLAN.md` §6.6), ни одного `.big/.w3d/.dds/.tga/.map/.csf/.str`; игровые скриншоты — только по галочке, хранятся вне git.
- Сетевые обращения лаунчера к чужим сервисам (`UpdateManager` → `raw.githubusercontent.com/MYSOREZ/…`, `files/update/remote_config.ini`, GeneralsOnline) — данных EA не передают, но фиксируем (вопрос 5.2).

## 5. Открытые вопросы к Android-платформе

1. **E1-15, логи в первом APK.** Будет ли «Отправить отчёт» (`bfme-report_*.zip`, AEI, tombstone, Java-исключения, `device.json`) или только «Поделиться» форка? Без данных игры движок не стартует, и на `e9292c9` Часть 1 даёт «Файлы логов пока не найдены»: загрузка `.so`, EGL и драйвер не проверяются. Нужен способ проверить это без файлов EA (`crash-selftest`, синтетическая GPU-сцена — `TEST-PLAN.md` §8 п. 3).
2. **`UpdateManager` включён по умолчанию** (`KEY_AUTO = true`): при каждом открытии лаунчера тянет подписанный манифест из `MYSOREZ/GeneralsZH-Android-Port/updates`, пишет `remote_config.ini`, может скачать и подменить `libmain.so`. Сейчас (манифест serial 12, engine seq 3277) подмену останавливает только несовпадение `requires_libs` (ANGLE и `libc++_shared` у нас совпадают, остальные нет), а проверка `seq` бессмысленна: `engine_build.txt` = `rev-list --count` на shallow-клоне (в сборке `e29eade` — `3`). Отключить или вырезать для BFME (вместе с GeneralsOnline / DataPack / сетевой диагностикой)? До этого Андрей проходит первый запуск в режиме полёта (1.6–1.7).
3. **Пакет, имя, версия:** `com.generalsx.zerohour`, «GeneralsZH», 1.3.0/10300 у всех сборок. Конфликт подписи с приложением форка; сборку не отличить ни в лаунчере, ни в логе (git sha пишется только в имя файла). Планируете свой `applicationId`, имя и `versionName` с sha и номером CI? (Смена пакета = удалить и ставить заново.)
4. **Первый запуск:** в каком APK появится экран «Нужны файлы BFME1» (`game-files-access.md` §6 п. 1) и что нажмёт «Запустить игру» без данных?
5. **E1-12a, детали для текста чек-листа:** точные названия кнопок; есть ли «Отмена»; запрос `POST_NOTIFICATIONS` для уведомления foreground-сервиса (Android 13+); что делает предпроверка при нехватке места; где `import-state.json` и лог импорта и попадает ли он в отчёт; ожидаемое время импорта 3,6 ГиБ на Pixel 8 Pro.
6. **E1-24 (через Форматы):** в `game-files-access.md` профиль `patch-2.22v5.5.4`, а у Андрея **2.22 v7.0.5** (`DATA-VERSION.md`) — без профиля v7.0.5 импорт покажет «модифицированная копия». Точный список обязательных файлов: нужны ли `lang\*.big` кроме `englishaudio.big`, `apt\`, `data\movies`, исключаются ли `.exe/.dll`.
7. **E1-12b:** когда уходит `MANAGE_EXTERNAL_STORAGE` вместе с записью файлов в папку пользователя и маркером `/sdcard/.generalszh_gamepath.txt`? До этого Андрею сказано не выдавать «Доступ ко всем файлам» (1.9).
8. **Запасной путь MTP** в `Android/data/com.generalsx.zerohour/files/GameData` (`game-files-access.md` §7 п. 4): проверен ли на Pixel 8 Pro, давать ли его Андрею?
9. **`allowBackup="true"`:** после переустановки Android может восстановить настройки (в том числе путь к папке). Выключить для тестовых сборок?
10. **Как придёт APK:** из CI (номер запуска, `.sha256` рядом, символы 90 дней) или ручной сборкой на боксе (`CI run 0`)? Что войдёт в первый APK из E1-13 (масштаб), E1-14 (Swappy, 30 FPS) и E1-35 (темп логики) — от этого зависят ожидания по плавности в 2.8.
