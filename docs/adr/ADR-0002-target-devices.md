## 2. Решение: сборка

| # | Решение | Комментарий |
|---|---|---|
| 1 | **Только `arm64-v8a`.** Android-сборку x86_64 и эмулятор не делаем: в форке x86_64 нет совсем (триплеты только `arm64-android`/`ios`/`osx`, `abiFilters arm64-v8a`, DXVK и ANGLE только под arm64), на боксе нет `/dev/kvm`. Smoke-проверка APK — на Pixel 8 Pro | одна сборка arm64 у всех игроков нужна для детерминизма lockstep (RESEARCH §5). Кросс-архитектурный детерминизм проверяем сравнением headless-сборки Linux x86_64 с arm64 на устройстве (E1-45) |
| 2 | **minSdk 29 (Android 10)** одновременно в Gradle, `CMakePresets.json` (`ANDROID_PLATFORM android-29`) и триплете vcpkg | все Pixel на Tensor выходили с Android 12+. SDL3 Java и так без проверки вызывает API 29 (`InputDevice#isExternal`) |
| 3 | API 30+ (`ANativeWindow_setFrameRate`, `Surface.setFrameRate`) вызываем **только с проверкой версии** (`dlsym` или `SDK_INT >= 30`) | на Android 10 без него просто нет подсказки частоты |
| 4 | **targetSdk 35** в Э0, чтобы воспроизвести форк как есть. **После первой зелёной сборки переходим на targetSdk/compileSdk 36** (AGP ≥ 8.9.1) **одновременно с NDK r28+** | Android 16 требует: `OnBackInvokedCallback` для меню паузы (`KEYCODE_BACK` больше не приходит), edge-to-edge с обработкой вырезов, `appCategory="game"` (сохраняет ориентацию на sw ≥ 600dp). Источники в `platform-input.md` §2, п. 2b |
| 5 | **NDK r27.2 LTS** (`27.2.12479018`), `c++_shared`. **Страницы 16 КБ:** в пресет добавляем `-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON` (официальная опция r27, действует на FetchContent-зависимости и хуки); для DXVK — `link_args` с `-Wl,-z,max-page-size=16384` в `cmake/meson-arm64-android-cross.ini.in`; shared-зависимости vcpkg — те же флаги через триплет. Сейчас 13 из 16 `.so` в APK форка выровнены по 4 КБ: libmain, libmain60, SDL3, SDL3_image, openal, gamespy, dxvk_d3d8/d3d9, adrenotools, 3 хука | r27 по умолчанию выравнивает на 4 КБ. **В CI проверяем все `.so`:** LOAD-сегменты выровнены ≥ 2**14, конец `GNU_RELRO` кратен 0x4000. `zipalign -c -P 16` при `useLegacyPackaging true` ничего не доказывает: библиотеки в APK сжаты. **Запуск на 16-КБ ядре:** режим «Boot with 16KB page size» на Pixel 8 Pro требует разблокировать загрузчик с полным стиранием данных, возврат в обычный режим — ещё одно стирание (source.android.com/docs/core/architecture/16kb-page-size/16kb-developer-option). Это основной телефон Андрея, поэтому запуск только с его явного согласия на стирание или на запасном телефоне (§12 п. 11, E1-BACKLOG §6) |
| 6 | **Подпись нашим ключом вне git** (секрет CI или файл на боксе вне репозитория). `android/app/debug.keystore` из `bfme` удаляем | правило «ключи не кладём в git» |
| 7 | `useLegacyPackaging true` оставляем, пока в сборке есть libadrenotools и DXVK | без этого не работает загрузка драйвера и DXVK (B/android/app/build.gradle#L127) |

## 3. Решение: рендер

1. **GLES 3.0 по умолчанию** через системный драйвер (d3d8gles). Расширения GLES 3.1/3.2 **не обязательны**, любое расширение используем только после проверки `GL_EXTENSIONS` и с запасным путём.
2. **Vulkan 1.1 (DXVK 2.6) опционален**, включается в настройках лаунчера, **в Э1 автопереключения нет**. На **PowerVR (Pixel 10)** Vulkan скрыт по умолчанию и доступен только для драйвера ≥ 25.1 по списку (`gpu-driver-issues.md` №5).
3. **ANGLE** остаётся диагностическим переключателем, в том числе для A/B при артефактах. По умолчанию не включается.
4. **Падения и артефакты на Mali и PowerVR являются блокерами** (TEAM.md). На Adreno и прочих GPU это ошибки приоритета 2.
5. **Цвет:** работаем в «гамма-пространстве», как D3D8. `EGL_GL_COLORSPACE_SRGB` не запрашиваем, sRGB-форматы при перекодировке не используем (`gpu-driver-issues.md` №7).
6. **MSAA** на PowerVR по умолчанию выключено. d3d8gles сейчас MSAA не поддерживает (`CheckDeviceMultiSampleType` отвечает только `NONE`).

## 5. Особенности драйверов Mali и PowerVR под GLES 3.0 (кратко; полностью в `gpu-driver-issues.md`)

| Тема | Суть | Наше правило |
|---|---|---|
| **Форматы текстур** | DXT/S3TC (BC1–3) на Mali и PowerVR не поддерживается, на стоковых Adreno как правило тоже. ETC2/EAC входят в ядро GLES 3.0. ASTC LDR есть на Mali Valhall и PowerVR, но только как расширение `GL_KHR_texture_compression_astc_ldr` | Э1: декод DXT на CPU в RGBA8 (как в форке), магенты нет. Перекодировку в ETC2 включаем по триггеру (§8). ASTC позже |
| **Точность `mediump`** | На Mali и PowerVR `mediump` во фрагментном шейдере означает настоящий FP16 (10 бит мантиссы): UV на больших или повторяющихся текстурах (террейн, вода, дороги) «дрожат» | в FS UV и текстурная математика в `highp`, цвет и туман в `mediump`. Масштаб и сдвиги UV считаем в VS. Задача в бэклоге |
| **sRGB** | D3D8 не знает про sRGB. Конкретных багов драйверов не найдено | линейный RGBA8, без sRGB-поверхностей |
| **Динамические буферы** | Mali игнорирует `UNSYNCHRONIZED` и останавливает GPU (Dolphin, PPSSPP, Arm) | кольцо из 3 буферов с fence, обновления пачкой |
| **Тайловый рендер** | повторный bind FBO, частичный clear и отсутствие invalidate увеличивают трафик и нагрев | FBO привязываем один раз за кадр, делаем полный `glClear` и `glInvalidateFramebuffer(DEPTH, STENCIL)` |
| **PowerVR + Vulkan** | магента и искажения через DXVK, слабая производительность даже на драйвере 25.1, проблемы с 16-битными форматами | только GLES по умолчанию (§3.2) |
| **PowerVR + GL** | `glGenerateMipmap` при высоте больше ширины (PPSSPP) | мипы на CPU или при импорте |

## 6. Масштаб рендера при 2992×1344

- Факт: Pixel 8 Pro **по умолчанию работает в 2244×1008** («High resolution»), 2992×1344 включается вручную (`platform-input.md` §4).
- **Масштаб задаём целевой высотой 3D-сцены**, а не долей от нативного разрешения. **По умолчанию ~756p (≈1680×756)**. Пресеты: 50 / 67 / 75 / 100% от High (504p / 672p / 756p / 1008p) и «натив». Ширина считается по фактическому соотношению сторон и округляется до чётного.
- **Э1:** `SurfaceHolder.setFixedSize(w, h)` (масштабирует HWC, кода почти нет, интерфейс тоже становится мыльным). Это нужно для замеров.
- **Пересчёт координат ввода входит в решение Э1** (E1-13). `setFixedSize` в Э1 ломает ввод: SDL 3.4.2 `SDLSurface.java` нормирует касания по размеру поверхности (L125–126, L223–237), а мышь и перо берёт по сырому `getX()` (L272, L404, L419). При поверхности 1680×756 в окне 2244×1008 ввод сдвинется в 1,34 раза. Форк уже ловил такое: `dx8wrapper.cpp` `Resize_And_Position_Window` ~L1435. **[Проверено по исходникам, на устройстве нет.]** Критерий: на каждом пресете тап по 4 углам и кнопкам меню попадает в цель.
- **Э4:** сцена рисуется в FBO на внутреннем разрешении, затем один blit-апскейл, HUD рисуется поверх в нативном разрешении. На тайловых GPU FBO привязываем один раз за кадр, делаем полный clear и `glInvalidateFramebuffer`.
- Критерий Э1 «≥ 30 FPS» проверяем на 756p (значение по умолчанию) и на 100% High. Отдельно фиксируем результат при 2992×1344.

## 7. Частота кадров при 120-Гц дисплее

- **Логика только 30 Гц** (`LOGICFRAMES_PER_SECOND = 30`). `libmain60` не берём: другая сборка, несовместимая по сети и реплеям. Из APK её удаляем (42 МБ, E1-11).
- **По умолчанию 30 FPS.** При старте один раз вызываем `ANativeWindow_setFrameRate(30)` (API 30+, с проверкой версии), подача кадров идёт через **Swappy GL с фиксированным интервалом** 33,3 мс без авторежимов. Интеграция Swappy с EGL-контекстом SDL3 — задача платформы (E1-14):
  - Swappy GL работает **только на системном GLES**. На ANGLE (свой `libEGL_angle`) и Vulkan он выключен;
  - вместо `SDL_GL_SwapWindow` вызываем `SwappyGL_swap` с EGL-хэндлами из SDL3;
  - у форка нет `externalNativeBuild`, `.so` кладутся в `jniLibs` (B/android/app/build.gradle L86–90), поэтому Swappy собираем из AGDK или берём статическую библиотеку из AAR;
  - критерий: интервал 33,3 ± 2 мс у ≥ 99% кадров за 5 минут (до M2 на меню или shellmap, на сцене M2 повторяем в E1-41).
- **Режим 60 FPS** добавляем, только если движок интерполирует отрисовку между тиками логики. Проверяет Лид (E1-BACKLOG).
  - **Предварительный результат Лида (02.10.2026, grep по `src/GeneralsZH-Android-Port`):** `GENERALS_ONLINE_HIGH_FPS_RENDER=1` включён во всех сборках (B/CMakeLists.txt, «Unlocks the render framerate»). Он отвязывает частоту рендера и держит часть клиентских эффектов (частицы, FXList) на «legacy»-частоте 30 Гц (`GameClient::m_frameLegacy`, `ParticleSys.cpp`). **Интерполяции позиций Drawable между тиками логики не нашёл.** Значит, сейчас 60 FPS при логике 30 Гц дадут одинаковые соседние кадры для юнитов **[не проверено на устройстве]**.
- Нагрев и батарея: 30 FPS и 756p заметно снижают нагрузку **[оценка, замер QA на Pixel 8 Pro]**.

## 8. Текстуры: решение на Э1

1. **Э1: CPU-декод DXT в RGBA8** (уже в d3d8gles) **и замер PSS** на Pixel 8 Pro. Для десктопного GLES на Mesa нужен флаг принудительного CPU-декода, в CI он включён (§10).
2. **Перекодировку DXT в ETC2 при импорте включаем по триггеру:** PSS выходит за бюджет (6 ГБ устройство: бюджет определяем после замера **[оценка: ≤ 2,5 ГБ PSS]**) **или** загрузка карты занимает больше 30 с.
   - Кодировщик и кэш (на телефоне при импорте, результат в `getExternalFilesDir`, не в git и не в APK) делают **«Форматы и данные»**.
   - Загрузку ETC2 в d3d8gles делает **Android-платформа**. Внутренний FOURCC для ETC2 допустим **только внутри d3d8gles**. В DXVK-пути такая текстура не появляется: там остаётся DXT или CPU-декод.
   - CPU-декод сохраняется как запасной путь. ASTC рассматриваем позже.
3. Альфу DXT1 (punch-through, листва) после перекодировки проверяем глазами (скриншот-тест QA).

## 9. Данные игры

- Движок читает **только `getExternalFilesDir(null)/GameData/`**: обычные пути, без особых разрешений.
- **SAF-импорт с копированием делаем в Э1** (`ACTION_OPEN_DOCUMENT_TREE`, потоковое копирование с SHA-256 по манифесту). Запасной путь: MTP или `adb push` в `Android/data/<pkg>/files/GameData`.
- **`MANAGE_EXTERNAL_STORAGE` удаляем из манифеста, когда заработает импорт.** Пока что оставляем его только для разработки.
- VFS понимает обе сигнатуры архивов: **`BIG4` (BFME1) и `BIGF` (Generals)**. Порядок монтирования: оригинал BFME1, затем 2.22, затем `MobileLayer/`.
- Подробности (UX, манифест, каталоги): `docs/game-files-access.md`.

**Десктопный GLES на Mesa не повторяет Mali:** llvmpipe, судя по таблице Mesa, объявляет S3TC, и d3d8gles обойдёт CPU-декод (`gles_pipeline.cpp` L435–438) **[по исходникам, не проверено]**; `mediump` там считается в fp32. Поэтому в CI включён флаг принудительного CPU-декода текстур, а точность шейдеров (`highp`/`mediump`, E1-16) проверяем только на устройстве.

Для каждого прогона фиксируем: модель, версию Android, `GL_RENDERER`/`GL_VERSION`, версию драйвера, бэкенд, масштаб, FPS p50/p1, PSS, температуру (через `thermalservice`/Perfetto), лог `[d3d8gles] … (s3tc=?)`. Список проверок на эталоне: `gpu-driver-issues.md` §8.

## 11. Последствия
- Android 9 (API 28) больше не поддерживается: −1 версия против форка. Redmi Note 8 Pro и подобные на Android 9 отпадают. Для Pixel ничего не меняется.
- Переход на targetSdk 36 и NDK r28+ — отдельная задача после первой зелёной сборки (AGP ≥ 8.9.1 требует Gradle ≥ 8.11.1, образ CI придётся обновить). До тех пор 16 КБ обеспечиваем `ANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON` и `link_args` DXVK.
- Эмулятора в CI нет: каждая smoke-проверка APK требует Pixel 8 Pro. Запуск на 16-КБ ядре без согласия Андрея на стирание или запасного телефона не проверяется, остаётся только проверка ELF в CI.
- Устройств Pixel на G1, G2, G4 и G5 у команды нет, поэтому заявить «блокеры на PowerVR закрыты» до появления Pixel 10 у друга нельзя. Это отмечено в рисках бэклога.
- Требование ОЗУ ≥ 6 ГБ сужает круг Android-устройств друзей (не Pixel).

## Изменения 02.10.2026 (после ревью Android-платформы и Форматов)

Все замечания Android-платформы к ADR приняты Лидом. Строки сверены платформой с форком на `8ef2349`. По исходникам, без устройства, проверены два пункта: сдвиг касаний при `setFixedSize` и S3TC в llvmpipe.

1. **§2 п. 5, 16 КБ.** Вместо ручных флагов линкера: `-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON` в пресете, `link_args` для DXVK в `cmake/meson-arm64-android-cross.ini.in`. CI проверяет все `.so`: LOAD ≥ 2**14 и конец `GNU_RELRO` кратен 0x4000. Проверку `zipalign -c -P 16` убрали как доказательство: при `useLegacyPackaging true` она ничего не показывает. Добавлен факт: 13 из 16 `.so` форка выровнены по 4 КБ. Запуск в режиме «Boot with 16KB page size» на Pixel 8 Pro делаем только с явного согласия Андрея на стирание или на запасном телефоне (новый §12 п. 11, E1-BACKLOG §6). §1 и §10 (ярус A) обновлены так же.
2. **§2 п. 1 и §10, эмулятор x86_64 убран.** В форке x86_64 нет, на боксе нет `/dev/kvm`. Smoke-проверка идёт на Pixel 8 Pro. Детерминизм между архитектурами проверяем сравнением headless Linux x86_64 с arm64 на устройстве (E1-45). Строка «Эмулятор x86_64 в CI» удалена из матрицы QA.
3. **§6, ввод.** Пересчёт координат ввода при `setFixedSize` входит в решение Э1 и в E1-13: SDL 3.4.2 нормирует касания по размеру поверхности, а мышь и перо берёт по сырому `getX()`.
4. **§7, Swappy.** Swappy GL работает только на системном GLES, на ANGLE и Vulkan он выключен. `SwappyGL_swap` вместо `SDL_GL_SwapWindow`. Сборка из AGDK или статическая библиотека из AAR, потому что у форка нет `externalNativeBuild`. Критерий темпа кадров перенесён из E1-14. Удаление `libmain60` (42 МБ) входит в E1-11 (§1 и §7).
5. **§8 и §10, десктопный GLES на Mesa.** llvmpipe объявляет S3TC, `mediump` считается в fp32, поэтому Mali он не повторяет. В CI включён флаг принудительного CPU-декода текстур, точность шейдеров проверяем только на устройстве.
6. **§1, §11, §12 п. 3:** AGP 8.9.x требует Gradle ≥ 8.11.1, образ CI (Gradle 8.9) придётся обновить (E1-19).
7. **§11:** добавлены последствия: эмулятора нет, 16-КБ ядро проверяем условно.
8. Решение Лида в конце файла (п. 2 «16 КБ: r27.2 + флаги сейчас») уточнено пунктом 1 выше: вместо ручных флагов теперь `ANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON`.
